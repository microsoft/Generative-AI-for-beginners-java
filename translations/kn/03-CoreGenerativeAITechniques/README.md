## ಪರಿಶೀಲನೆ

ನಾಲ್ಕು ಪ್ರತ್ಯೇಕ ಜಾವಾ ಪ್ರೋಗ್ರಾಮುಗಳು ಚಾಟ್, ಸಂಭಾಷಣೆ ಇತಿಹಾಸ, ಫಂಕ್ಷನ್ ಕರೆದೊಯ್ಯುವಿಕೆ, ಸಂಪೂರ್ಣ ದಸ್ತಾವೇಜು ರಿಟ್ರೀವಲ್ ಆಗ್ಮೆಂಟೆಡ್ ಜೆನೆರೇಷನ್ (RAG), ಮತ್ತು ಜವಾಬ್ದಾರಿಯುತ ಏಐ ಪ್ರತಿಕ್ರಿಯಾ ನಿರ್ವಹಣೆಯನ್ನು ತೋರಿಸುತ್ತವೆ. ಎಲ್ಲಾ ಚಾಟ್ ವಿನಂತಿಗಳು ಡೀಫಾಲ್ಟ್ ಆಗಿ **GPT-5.6 ಲೂನಾ ಜೊತೆಗೆ ಯಾವುದೇ ಕಾರಣವಿಲ್ಲದ ತರ್ಕ ಶ್ರಮ** ಗುರಿಯಾಗಿವೆ.

ಈ ಉದಾಹರಣೆಗಳು ಅಧಿಕೃತ OpenAI ಜಾವಾ SDK ನ್ನು Azure OpenAI ನ v1 ಎಂಡ್ ಪೋಯಿಂಟ್ ಜೊತೆಗೆ ಬಳಸುತ್ತವೆ, [ಮೈಕ್ರೋಸಾಫ್ಟ್SDK ಮಾರ್ಗದರ್ಶನ](https://learn.microsoft.com/azure/ai-foundry/openai/supported-languages) ಯನ್ನು ಅನುಸರಿಸಿ. ಹಳೆಯ `azure-ai-openai` ಪ್ಯಾಕೇಜ್ ಇನ್ನು ಅವಲಂಬನೆಯಲ್ಲ. ಚಾಟ್ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಗಳು ಈಗಿನ ಸಂದೇಶ ಆಧಾರಿತ ಕಾರ್ಯವ್ಯೂಹಗಳನ್ನು ಕಲಿಸುವುದು ಈಗಿಗೂ ಉಳಿಸಿದೆ; ಇತರೆ API ಆಯ್ಕೆಗಳಿಗಾಗಿ [OpenAI ಜಾವಾ SDK](https://github.com/openai/openai-java#microsoft-azure) ನೋಡಿ.

## ಪ್ರಾರಂಭಿಸುವುದು

ರೆಪೊ ರೂಟ್ ನಿಂದ, ನಿಮ್ಮ ಶೆಲ್ಲಿನಲ್ಲಿ ಸಂಪನ್ಮೂಲ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಮತ್ತು ಐಚ್ಛಿಕ ನಿಯೋಜನೆ ಅತಿಕ್ರಮಣವನ್ನು ಹೊಂದಿಸಿ.

**ವಿಂಡೋಸ್ ಪವರ್‌ಶೆಲ್:**

```powershell
$env:AZURE_OPENAI_ENDPOINT = "https://your-resource.openai.azure.com/"
$env:AZURE_OPENAI_DEPLOYMENT = "gpt-5.6-luna"
Set-Location 03-CoreGenerativeAITechniques/examples
mvn -B -ntp clean test
```

**ಲಿನಕ್ಸ್/ಮ್ಯಾಕ್‌ಒಎಸ್:**

```bash
export AZURE_OPENAI_ENDPOINT="https://your-resource.openai.azure.com/"
export AZURE_OPENAI_DEPLOYMENT="gpt-5.6-luna"
cd 03-CoreGenerativeAITechniques/examples
mvn -B -ntp clean test
```

ಪರೀಕ್ಷೆಗಳಿಗೆ ಯಾವುದೇ Azure ಪ್ರಮಾಣಪತ್ರಗಳು ಅಥವಾ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಬೇಕಾಗಿರುವುದಿಲ್ಲ. ಮೇವನ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪರಿಸರ ಫೈಲ್ ಓದುವುದಿಲ್ಲ; ಲೈವ್ ಉದಾಹರಣೆ ಆರಂಭಿಸುವಾಗ ಬಳಸಿ ಕೊಳ್ಳುತ್ತಿರುವ ಶೆಲ್ ನಲ್ಲಿ ವ್ಯರಿಗಳನ್ನು ಹೊಂದಿಸಿ. ಐಡಿಇ ಆರಂಭಿಸುವಾಗ ನಿಮ್ಮ ಆರಂಭಿಸಿರುವ ಸಂರಚನೆಯ ಮೂಲಕ ಪೂರಕವಾದ ಪರಿಸರವನ್ನು ಪರಿಶೀಲಿಸಿ.

## ಮಾದರಿ ಆಯ್ಕೆ ಮಾರ್ಗದರ್ಶಿ

| ಪರಿಸರ ಚರ | ಅರ್ಥ | ಮೂಲಧಾರಣೆ |
| --- | --- | --- |
| `AZURE_OPENAI_ENDPOINT` | HTTPS Azure ಸಂಪನ್ಮೂಲ ರೂಟ್ ಅಥವಾ ಈಗಾಗಲೇ ನಾರ್ಮಲೈಜ್ಡ್ `/openai/v1` URL | ಲೈವ್ ರನ್ ಗಾಗಿ ಅಗತ್ಯವಿದೆ |
| `AZURE_OPENAI_DEPLOYMENT` | ಚಾಟ್ ನಿಯೋಜನೆಯ ಹೆಸರು, ಮಾದರಿ ಆವೃತ್ತಿ ಅಲ್ಲ | `gpt-5.6-luna` |
| `AZURE_OPENAI_EMBEDDING_DEPLOYMENT` | ವಿಭಿನ್ನ ಎम्बೆಡ್ಡಿಂಗ್ ನಿಯೋಜನೆ, ಈ ನಾಲ್ಕು ಪ್ರೋಗ್ರಾಮ್ಗಳಿಂದ ಉಪಯೋಗಿಸುವುದಿಲ್ಲ | `text-embedding-3-small` |

ಖಾಲಿ ನಿಯೋಜನೆ ಅತಿಕ್ರಮಣವು ಡೀಫಾಲ್ಟ್‌ಗಳನ್ನು ಬಳಸುತ್ತದೆ. ಸಂರಚನೆ `/openai/v1` ಅನ್ನು ಸರಿಯಾಗಿ ಒಂದೇ ಬಾರಿ ಸೇರಿಸುತ್ತದೆ ಮತ್ತು ಎಂಡ್‌ಪಾಯಿಂಟ್‌ನಲ್ಲಿ ಪ್ರಮಾಣಪತ್ರಗಳು, ಕ್ವೇರಿ ಸ್ಟ್ರಿಂಗ್‌ಗಳು ಮತ್ತು ಹಳೆಯ ನಿಯೋಜನೆ ಮಾರ್ಗಗಳನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ.

ಪ್ರತಿ ಚಾಟ್ ವಿನಂತಿ ಸ್ಪಷ್ಟವಾಗಿ `reasoningEffort(ReasoningEffort.NONE)` ಮತ್ತು `maxCompletionTokens(...)` ನ್ನು ಹೊಂದಿರುತ್ತದೆ. ಯಾವುದೇ ವಿನಂತಿಯು `temperature`, `top_p`, ಅಥವಾ ಹಳೆಯ ಪೂರ್ಣಗೊಳಿಸುವ-ಟೋಕನ್ ಆಯ್ಕೆಯನ್ನು ಹೊಂದುವುದಿಲ್ಲ. ಇದರಲ್ಲಿ ಟೂಲ್ ಆಯ್ಕೆ ಮತ್ತು ಟೂಲ್ ಫಲಿತಾಂಶಗಳ ನಂತರದ ವಿಚಾರವೂ ಸೇರಿವೆ. GPT-5.6 ಚಾಟ್ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆ ಕಾರ್ಯಪಧ ಟೂಲ್‌ಗಳಿಗೆ ಕಾರಣಶಕ್ತಿ `none` ಬೇಕಾಗುತ್ತದೆ; [ಮೈಕ್ರೋಸಾಫ್ಟ್ ಚಾಟ್ ಮಾರ್ಗದರ್ಶನ](https://learn.microsoft.com/azure/ai-foundry/openai/how-to/chatgpt) ನೋಡಿ.

**ಈ ಅಧ್ಯಾಯದಲ್ಲೊಂದು ಸ್ಟ್ರೀಮಿಂಗ್ ಅಥವಾ ಎಂಬೆಡ್ಡಿಂಗ್ ಪ್ರವೆಶದ್ವಾರವಿಲ್ಲ.** ಓದುಗ ತನ್ನ ಸಂಪೂರ್ಣ ದಸ್ತಾವೇಜುಗಳನ್ನು ಪಡೆಯುತ್ತಾನೆ, ವೆಕ್ಟರ್‌ಗಳನ್ನು ಅಲ್ಲ. ನೀವು ಅದನ್ನು ಎಂಬೆಡ್ಡಿಂಗ್ ಜೋಡಿಸಿದರೆ, `text-embedding-3-small` ಮುಂತಾದ ಪ್ರತ್ಯೇಕ ಎಂಬೆಡ್ಡಿಂಗ್ ನಿಯೋಜನೆಯನ್ನು ಬಳಸಿ, ಲೂನಾವನ್ನು ಎಂದಿಗೂ ಬಳಸಬೇಡಿ.

## ಟ್ಯುಟೋರಿಯಲ್ 1: ಎಲ್‌ಎಲ್‌ಎಮ್ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಗಳು ಮತ್ತು ಚಾಟ್

ಮೂಲ: [LLMCompletionsApp.java](../../../03-CoreGenerativeAITechniques/examples/src/main/java/com/example/genai/techniques/completions/LLMCompletionsApp.java).

ಪ್ರೋಗ್ರಾಮ್ ಸರಳ ಜಾವಾ ಸ್ಟ್ರೀಮ್ಸ್ ವಿವರಣೆ, ಎರಡು-ತಿರುವಿನ ಹ್ಯಾಶ್‌ಮ್ಯಾಪ್/ಟ್ರೀಮ್ಯಾಪ್ ಸಂಭಾಷಣೆ ಮತ್ತು ಸಂವಾದಾತ್ಮಕ ಚಾಟ್ ನಡೆಸುತ್ತದೆ. ಎರಡನೇ ತಿರುವು ಮೊದಲ ಸಹಾಯಕ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಒಳಗೊಂಡಿದೆ; ಪ್ರತಿ ಸಂವಾದಾತ್ಮಕ ತಿರುವು ಹಿಂದೆ ಉಳಿದ ಸಂಭಾಷಣೆಯನ್ನು ಕೂಡ ಕಳುಹಿಸುತ್ತದೆ.

```java
var request = config.chatOptions(200)
        .addSystemMessage("You are a helpful Java expert.")
        .addUserMessage("Explain Java streams briefly.")
        .build();
String answer = ChatResponses.text(client.chat().completions().create(request));
```

`config.chatOptions(...)` ನಿಯೋಜನೆ ಮತ್ತು ಸ್ಪಷ್ಟ ಕಾರಣಶಕ್ತಿ ಸೆಟ್ಟಿಂಗ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ. ಸಂವಾದಾತ್ಮಕ ಚಾಟ್ ಖಾಲಿ ಸಾಲುಗಳನ್ನು ಬಿಟ್ಟಿಡುತ್ತದೆ, `exit` ಅಥವಾ EOF ಮೇಲಾಗುತ್ತದಷ್ಟರಲ್ಲಿ ಮುಕ್ತಾಯಗೊಳ್ಳುತ್ತದೆ, ಮತ್ತು ಸಿಸ್ಟಮ್ ಸಂದೇಶ ಹಾಗೂ ಒಂಬತ್ತು ಪೂರ್ಣಗೊಂಡ ಬಳಕೆದಾರ/ಸಹಾಯಕ ತಿರುವುಗಳನ್ನು ಇಟ್ಟಿಡುತ್ತದೆ. ತಿರುವು-ಎಣಿಕೆ ಕಡಿತ ಶಿಕ್ಷಣಾಭಿಪ್ರಾಯವಾಗಿದ್ದು, ನಿಖರ ಟೋಕನ್-ಬಜೆಟ್ ಖಚಿತತೆ ಅಲ್ಲ.

ಉದಾಹರಣೆಗಳ ಡೈರೆಕ್ಟರಿಯಿಂದ:

```powershell
mvn -ntp compile exec:java "-Dexec.mainClass=com.example.genai.techniques.completions.LLMCompletionsApp"
```

ಮೂರು ಪ್ರಾಥಮಿಕ ಉತ್ತರಗಳನ್ನು ನಿರೀಕ್ಷಿಸಿ, ನಂತರ `ನೀವು:` ಪ್ರಾಂಪ್ಟ್ ಬರುತ್ತದೆ. ಪ್ರತಿ ಖಾಲಿ-ಬರುವ ಸಂವಾದಾತ್ಮಕ ಪ್ರಶ್ನೆ ಒಂದು ವಿನಂತಿಯನ್ನು ಹೆಚ್ಚಿಸುತ್ತದೆ. ಪೂರ್ಣಗೊಳಿಸುವ ಮಿತಿಗಳು ಪ್ರತಿ ಸಂವಾದಾತ್ಮಕ ತಿರುವಿಗೆ ಕ್ರಮವಾಗಿ 200, 300, 400, ನಂತರ 500 ಟೋಕನ್ ಗಳು ಆಗಿವೆ.

## ಟ್ಯುಟೋರಿಯಲ್ 2: ಫಂಕ್ಷನ್ ಕರೆದೊಯ್ಯುವುದು

ಮೂಲ: [FunctionsApp.java](../../../03-CoreGenerativeAITechniques/examples/src/main/java/com/example/genai/techniques/functions/FunctionsApp.java).

SDK ಟಿಪ್ಪಣ ಹಾಕಲಾದ `WeatherArguments` ಮತ್ತು `CalculationArguments` ದಾಖಲೆಗಳಿಂದ JSON ಯೋಚನೆಕೃತ (schema) ಗಳನ್ನು ಸೃಷ್ಟಿಸುತ್ತದೆ. ಬೇಡಿಕೆಯಾದ ಟೂಲ್ ಆಯ್ಕೆ ಪ್ರತಿಯೊಂದು ಉದಾಹರಣೆಯು ಮಾದರಿಯ ಸಹಾಯವಿಲ್ಲದ ಉತ್ತರ ಪಡೆಯುವ ಬದಲು ಟೂಲ್ ಪ್ರೋಟೋಕಾಲ್ ಅನ್ನು ಅಧ್ಯಯನ ಮಾಡುತ್ತದೆ.

1. ಅನುಮತಿಸಿದ ಟೂಲ್ ಜೊತೆಗೆ ಪ್ರಶ್ನೆಯನ್ನು ಕಳುಹಿಸಿ, ಕಾರಣಶಕ್ತಿ `none` ಮತ್ತು 300-ಟೋಕನ್ ಪೂರ್ಣಗೊಳಿಸುವ ಮಿತಿ ಇರಲಿ.
2. `tool_calls` ಅಂತ್ಯ ಕಾರಣ ಬೇಕು, ಫಂಕ್ಷನ್ ಹೆಸರು ಮತ್ತು ಕರೆ ID ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ, ಮತ್ತು ಟೈಡ್ JSON ಪದಾರ್ಥಗಳನ್ನು ವಿಶ್ಲೇಷಿಸಿ.
3. ಸ್ಥಳೀಯ ಫಂಕ್ಷನ್ ನಡಿಸಲಾಗುತ್ತದೆ. ಮಾದರಿ ಜಾವಾ ಅಥವಾ ಯಾವುದೇ ಕೋಡ್ ಅನ್ನು ನಡಿಸುವುದಿಲ್ಲ.
4. ಸಹಾಯಕ ಟೂಲ್-ಕರೆ ಸಂದೇಶವನ್ನು ಒಂದೇ ಬಾರಿ ಸೇರಿಸಿ, ಮತ್ತು ಪ್ರತಿಯೊಂದು ಫಲಿತಾಂಶವನ್ನು ಅದರ ಹೊಂದಿಕೊಂಡ `tool_call_id` ಸಹಿತ ಬರೆದುಕೊಳ್ಳು.
5. ಯಾವುದೇ ಟೂಲ್‌ಗಳಿಲ್ಲದೆ ಒಂದೇಕಡೆ 300 ಟೋಕನ್ ವಿನಂತಿ ಕಳುಹಿಸಿ ಪೂರ್ಣಗೊಳ್ಳಲಾದ, ಖಾಲಿ ಇಲ್ಲದ ಉತ್ತರವನ್ನು ಬೇಕಾಗಿರಿಸಿ.

`get_weather` **ನಕಲಿ** ಮತ್ತು ಲೈವ್ ವಾತಾವರಣ ಮಾಹಿತಿ ನೀಡುವುದಿಲ್ಲ. ಇದು ನಗರವನ್ನು ಗೌರವಿಸುತ್ತದೆ ಮತ್ತು 22 ಡಿಗ್ರಿ ಸೆಲ್ಸಿಯಸ್ ಅನ್ನು ಫಾರೆನ್ಹೀಟ್ ಗೆ ಪರಿವರ್ತಿಸುತ್ತದೆ, ಕೇಳಿದಾಗ ಮಾತ್ರ. `calculate` exp4j ಮೂಲಕ ಪೂರೈಸಲಾದ ವ್ಯಾಕ್ಯವನ್ನು ಎವ್ಯಾಲ್ಯೂಟ್ ಮಾಡುತ್ತದೆ, `15% of 240` ಮತ್ತು `2 + 3 * 4` ಮುಂತಾದ ರೂಪಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ, ಮತ್ತು ಖಾಲಿ, ಅತಿದೊಡ್ಡ, ಅಮಾನ್ಯ ಅಥವಾ ಅಪೂರ್ಣ ಗಣನೆಗಳನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ. ಇದು ಹಣಕಾಸು ದಶಮಾಂಶ ಸರಿಯಾದತೆ ಇಲ್ಲದ ಫ್ಲೋಟಿಂಗ್ ಪಾಯಿಂಟ್ ಗಣಿತವನ್ನು ಬಳಸುತ್ತದೆ.

```powershell
mvn -ntp compile exec:java "-Dexec.mainClass=com.example.genai.techniques.functions.FunctionsApp"
```

`Function: get_weather`, ನಕಲಿ ಸಿಯಾಟಲ್ ವಾತಾವರಣ, `Function: calculate`, `Function result: 36`, ಮತ್ತು ಎರಡು ಅಂತಿಮ ಉತ್ತರಗಳನ್ನು ನಿರೀಕ್ಷಿಸಿ. ಯಾವುದೇ stdin ಅಥವಾ ಬಾಹ್ಯ ವಾತಾವರಣ ಪ್ರಮಾಣಪತ್ರಗಳು ಬೇಕಾಗಿಲ್ಲ. ಯಶಸ್ವಿ ಚಾಲನೆ ಸರಿಯಾಗಿ ನಾಲ್ಕು ಚಾಟ್ ವಿನಂತಿಗಳನ್ನು ಬಳಸುತ್ತದೆ.

## ಟ್ಯುಟೋರಿಯಲ್ 3: RAG (ರಿಟ್ರೀವಲ್-ಆಗ್ಮೆಂಟೆಡ್ ಜೆನೆರೇಷನ್)

ಮೂಲ: [SimpleReaderDemo.java](../../../03-CoreGenerativeAITechniques/examples/src/main/java/com/example/genai/techniques/rag/SimpleReaderDemo.java). ಇನ್ಪುಟ್: [document.txt](../../../03-CoreGenerativeAITechniques/examples/document.txt).

ಈ ಪರಿಚಯಾತ್ಮಕ RAG ಉದಾಹರಣೆ ಒಂದು ಸಂಪೂರ್ಣ UTF-8 ದಸ್ತಾವೇಜುಗಾರನ್ನು ರಿಟ್ರೀವ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಪ್ರಶ್ನೆಯೊಂದಿಗೆ ಬಳಕೆದಾರ ಸಂದೇಶದಲ್ಲಿ ಸೇರಿಸುತ್ತದೆ. ಪ್ರತ್ಯೇಕ ಸಿಸ್ಟಮ್ ಸಂದೇಶ ಮಾದರಿಯನ್ನು ಸೂಚಿಸುತ್ತದೆ ದಸ್ತಾವೇಜಿನ ವಿಷಯವನ್ನು ನಂಬದ ಡೇಟಾ ಎಂದು ಮತ್ತು ಉತ್ತರವನ್ನು ಆ ಸ೦ದರ್ಭದಿಂದ ಮಾತ್ರ ನೀಡಲು. ದಸ್ತಾವೇಜು ಉತ್ತರ ಹೊಂದದಿದ್ದರೆ, ಕೇಳಿದ ಪ್ರತಿಕ್ರಿಯೆ: `ನನಗೆ ಒದಗಿಸಿದ್ದ ದಸ್ತಾವೇಜಿನಲ್ಲಿ ಆ ಮಾಹಿತಿ ಸಿಕ್ಕಿಲ್ಲ.`

ನೆಲೆಕರಣವು ಹಲ್ಲುಗಳನನ್ನು ಕಡಿಮೆ ಮಾಡಬಹುದು, ಆದರೆ ಔಟ್‌ಲೈನ್ ಗಳು ಅಥವಾ ಸಿಸ್ಟಮ್ ಸೂಚನೆಗಳು ನಿಖರತೆ ಖಚಿತಪಡಿಸುವುದಿಲ್ಲ ಅಥವಾ ಪ್ರತಿ ಪ್ರಾಂಪ್ಟ್ ಆದೇಶವನ್ನು ತಡೆಹಿಡಿಯುವುದಿಲ್ಲ. ಲೈವ್ ಉತ್ತರಗಳನ್ನು ಪರಿಶೀಲಿಸಿ. ಉತ್ಪಾದನಾ RAG ಸಾಮಾನ್ಯವಾಗಿ ಚಂಕಿಂಗ್, ರಿಟ್ರೀವಲ್, ಉಲ್ಲೇಖಗಳು, ಪ್ರವೇಶ ನಿಯಂತ್ರಣ ಮತ್ತು ಮೌಲ್ಯಮಾಪನವನ್ನು ಸೇರಿಸುತ್ತದೆ.

```powershell
mvn -ntp compile exec:java "-Dexec.mainClass=com.example.genai.techniques.rag.SimpleReaderDemo"
```

ಒಂದು ಪ್ರಶ್ನೆಯನ್ನು ನಮೂದಿಸಿ, ಉದಾಹರಣೆಗೆ `ಈ ದಸ್ತಾವೇಜು ಯಾವ ಪ್ರಮಾಣೀಕರಣ ವಿಧಾನವನ್ನು ವಿವರಿಸುತ್ತದೆ?`. ಮೈಕ್ರೋಸಾಫ್ಟ್ ಎಂಟ್ರಾ ಐಡಿ ಹತ್ತಿರದ ಉತ್ತರ ನಿರೀಕ್ಷಿಸಿ. ಪ್ರೋಗ್ರಾಮ್ ಒಂದು ಚಾಟ್ ವಿನಂತಿ ನಂತರ 500-ಟೋಕನ್ ಪೂರ್ಣಗೊಳಿಸುವ ಮಿತಿ ಜೊತೆಗೆ ನಿರ್ಗಮಿಸುತ್ತದೆ.

ಡೀಫಾಲ್ಟ್ ಕಡತ ಹುಡುಕಾಟವು ರೆಪೊ ರೂಟ್, ಅಧ್ಯಾಯ ಡೈರೆಕ್ಟರಿ ಅಥವಾ ಉದಾಹರಣೆ ಡೈರೆಕ್ಟರಿಯಿಂದ ಕೆಲಸ ಮಾಡುತ್ತದೆ. ಸ್ಪಷ್ಟವಾದ ಮಾರ್ಗ ಸಹ ಬೆಂಬಲಿಸಲಾಗಿದೆ:

```powershell
mvn -ntp compile exec:java "-Dexec.mainClass=com.example.genai.techniques.rag.SimpleReaderDemo" '-Dexec.args="C:/documents/my document.txt"'
```

ಇನ್ಪುಟ್ಗಳು ಖಾಲಿಯಾಗಿರಬಾರದು: ಗರಿಷ್ಠ 32 ಕಿಬಿ UTF-8 ದಸ್ತಾವೇಜು ಡೇಟಾ ಮತ್ತು 2,000 ಪ್ರಶ್ನೆ ಅಕ್ಷರಗಳು. ಕಳೆದುಕೊಂಡ ಕಡತಗಳು, ಖಾಲಿ/EOF ಪ್ರಶ್ನೆಗಳು, ಅತಿದೊಡ್ಡ ಇನ್ಪುಟ್‌ಗಳು ಇನ್ಫರೆನ್ಸ್ ಮುಂಚಿತವಾಗಿಯೇ ವಿಫಲವಾಗುತ್ತವೆ.

## ಟ್ಯುಟೋರಿಯಲ್ 4: ಜವಾಬ್ದಾರಿಯುತ ಏಐ

ಮೂಲ: [ResponsibleAIDemo.java](../../../03-CoreGenerativeAITechniques/examples/src/main/java/com/example/genai/techniques/responsibleai/ResponsibleAIDemo.java).

ಆರ probe ಗಳಿಗೆ ಹಾನಿಕಾರಕ ಸೂಚನೆಗಳು, ದ್ವೇಷ ಭಾಷಣ, ಗೌಪ್ಯತೆ, ವೈದ್ಯಕೀಯ ತಪ್ಪು ಮಾಹಿತಿ, ಅಕ್ರಮ ವಿಷಯಗಳು ಮತ್ತು ಒಬ್ಬ ಸಾಂಪ್ರದಾಯಿಕ ಜವಾಬ್ದಾರಿಯುತ ಏಐ ಪ್ರಶ್ನೆಯನ್ನು ಒಳಗೊಂಡಿವೆ. ಪ್ರೋಗ್ರಾಮ್ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ವೀಕ್ಷಿಸುತ್ತದೆ, ಪ್ರತಿಯೊಂದು probe ನೂ ಹಾಕಲು ಫಿಲ್ಟರ್ ಅಪೇಕ್ಷಿಸುವುದಿಲ್ಲ.

| ಫಲಿತಾಂಶ | ಸಾಕ್ಷ್ಯ |
| --- | --- |
| `FILTERED` | ಸ್ಪಷ್ಟವಾದ `content_filter` / `ResponsibleAIPolicyViolation` ದೋಷ ಕೋಡ್ ಅಥವಾ ಪೂರ್ಣಗೊಳ್ಳುವಿಕೆ `content_filter` ಅಂತ್ಯ ಕಾರಣ |
| `REFUSED` | ಖಾಲಿ-ಇಲ್ಲದ ರಚಿತ `message.refusal` ಕ್ಷೇತ್ರ |
| `POSSIBLE_REFUSAL` | ಸಾಮಾನ್ಯ ಪಠ್ಯದಲ್ಲಿ ಒಂದು ಆರಂಭಿಕ ನಿರಾಕರಣಾ ವಾಕ್ಯ; ಪರಿಶೀಲನೆ ಅಗತ್ಯವಿರುವ ಸೂತ್ರಮೂಲಕ |
| `GENERATED` | ಪೂರ್ಣಗೊಂಡ ಖಾಲಿ-ಇಲ್ಲದ ಪ್ರತಿಕ್ರಿಯೆ; ಅದರ ವಿಷಯ ಸುರಕ್ಷಿತವಾಗಿದೆ ಎಂಬ প্ৰಮಾಣ ಇಲ್ಲ |

ಸಾಮಾನ್ಯ HTTP 400 **ಫಿಲ್ಟರ್ ಆದೆಯೆಂಬ ಸಾಕ್ಷ್ಯವಲ್ಲ**. ಅಮಾನ್ಯ ಪರಿಮಾಣಗಳು, ಪ್ರಮಾಣಪತ್ರ ವಿಫಲತೆಗಳು, ದರ-ಮಿತಿ, ಸರ್ವರ್ ದೋಷಗಳು, ಕೆಟ್ಟ ಪ್ರತಿಕ್ರಿಯೆಗಳು ಮತ್ತು ಶೀರ್ಷಿಕೆಯ ಕಡಿತವು ಸರಿಯಾದ ಲಾಭವಾಗುವ ಬದಲು ರನ್ನ ಉಪಯೋಗವನ್ನು ಯಶಸ್ವಿಯಾಗಿ ನಿರೋಧಿಸುತ್ತವೆ. "ಹಾನಿಕಾರಕ ವಿಷಯ" ಎಂಬ ಬೃಹತ್ ಪದಗಳನ್ನು ಸಾಂಪ್ರದಾಯಿಕ ವಿವರಣೆಯಲ್ಲಿ ನಿರಾಕರಣೆ ಆಗಾರಂತೆ ಪರಿಗಣಿಸಲಾಗುವುದಿಲ್ಲ.

```powershell
mvn -ntp compile exec:java "-Dexec.mainClass=com.example.genai.techniques.responsibleai.ResponsibleAIDemo"
```

ಆರು ವರ್ಗ ಫಲಿತಾಂಶಗಳು ಮತ್ತು ಅವಲೋಕನಗಳು ಸುರಕ್ಷತಾ ಪ್ರಮಾಣಪತ್ರವಲ್ಲ ಎಂದು ಸಾರುವಸಾರಾಂಶ ನಿರೀಕ್ಷಿಸಿ. ಪ್ರತಿ ಪ್ರೋಬ್ 300 ಟೋಕನ್ ಪೂರ್ಣಗೊಳಿಸುವ ಮಿತಿಯನ್ನು ಹೊಳೆಯುತ್ತದೆ. ಅನಿರೀಕ್ಷಿತ ಉತ್ಪಾದನೆಗಳು ಮತ್ತು ಸಮಭಾವ್ಯ ನಿರಾಕರಣೆಗಳನ್ನು ಕೈಯಿಂದ ಪರಿಶೀಲಿಸಿ; ಸಾಂಪ್ರದಾಯಿಕ ಹೋಲಿಕೆ ಸುಸಂಸ್ಕೃತ ಜವಾಬ್ದಾರಿಯತನ ವಿವರಣೆಯನ್ನು ನೀಡುತ್ತದೆ. ಯಾವುದೇ stdin ಅಗತ್ಯವಿಲ್ಲ.

## ಉದಾಹರಣೆಗಳ ನಡುವೆ ಸಾಮಾನ್ಯ ಮಾದರಿಗಳು

[AzureOpenAIConfig.java](../../../03-CoreGenerativeAITechniques/examples/src/main/java/com/example/genai/techniques/AzureOpenAIConfig.java) ಎಂಡ್‌ಪಾಯಿಂಟ್ ಸಾಮಾನ್ಯೀಕರಣ, ನಿಯೋಜನೆ ಅತಿಕ್ರಮಣಗಳು, ಕೀಲಿಯಿಲ್ಲದ ಪ್ರಮಾಣೀಕರಣ ಮತ್ತು ಚಾಟ್ ಆಯ್ಕೆಗಳನ್ನು ಕೇಂದ್ರಗೊಳಿಸುತ್ತದೆ:

```java
OpenAIClient client = OpenAIOkHttpClient.builder()
        .baseUrl(config.endpoint())
        .credential(BearerTokenCredential.create(AuthenticationUtil.getBearerTokenSupplier(
                new DefaultAzureCredentialBuilder().build(),
                "https://cognitiveservices.azure.com/.default")))
        .timeout(Duration.ofSeconds(60))
        .maxRetries(0)
        .build();
```

ಟೋಕನ್ ಸರಬರಾಜುದಾರ ಅಗತ್ಯವಿರುವಂತೆ ಪ್ರವೇಶ ಟೋಕನ್ಗಳನ್ನು تازಾ ಮಾಡುತ್ತದೆ. ಟೋಕನ್ ಗಳನ್ನು ಲಾಗ್ ಮಾಡಬೇಡಿ ಅಥವಾ ಇದನ್ನು API ಕೀ ಯಿಂದ ಬದಲಾಯಿಸಬೇಡಿ. ಪ್ರತಿಯೊಂದು ಪ್ರೋಗ್ರಾಮ್ ತನ್ನ ಕ್ಲೈಂಟ್ ಅನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತದೆ ಮತ್ತು `finally` ಅಥವಾ ಅದರದೇ `AutoCloseable` ರಾಪ್ಪರ್ ಮೂಲಕ ಮುಚ್ಚುತ್ತದೆ; SDK ನ `OpenAIClient` ಸ್ವಯಂ `AutoCloseable` ಅಲ್ಲ.

[ChatResponses.java](../../../03-CoreGenerativeAITechniques/examples/src/main/java/com/example/genai/techniques/ChatResponses.java) ಪೂರ್ಣಗೊಂಡ, ಖಾಲಿ-ಇಲ್ಲದ ಪಠ್ಯಮೂಲಕ ಉತ್ತರವನ್ನು ಬೇಕಾಗಿರಿಸುತ್ತದೆ. ಖಾಲಿ ಆಯ್ಕೆಗಳು, ನಿರಾಕರಣೆಗಳು, ಫಿಲ್ಟರ್ ಗಳು ಮತ್ತು ಶೀರ್ಷಿಕೆ ಉತ್ತರಗಳು ಯಶಸ್ಸಾಗಿ ಮೌನವಾಗಿ ಮುದ್ರಿಸಲ್ಪಡುವುದಿಲ್ಲ. ಜವಾಬ್ದಾರಿಯುತ ಏಐ ಉದಾಹರಣೆ ನಿರೀಕ್ಷಿತ ಫಿಲ್ಟರ್/ನಿರಾಕರಣೆ ಪರಿಣಾಮಗಳನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ನಿರ್ವಹಿಸುತ್ತದೆ. ನಿರ್ವಹಿಸಲ್ಪಟ್ಟಿಲ್ಲದ ವಿಫಲತೆಗಳು ಜಾವಾ/ಮೇವನ್ ಪ್ರಕ್ರಿಯೆಗೆ ಶೂನ್ಯವಲ್ಲದ ನಿರ್ಗಮನ ಕೋಡ್ ಅನ್ನು ನೀಡುತ್ತದೆ.

**ಸ್ವಯಂಚಾಲಿತ SDK ಮರುಪ್ರಯತ್ನಗಳು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲ್ಪಟ್ಟಿವೆ** ಹಂಚಿಕೆಯ ಕಡಿಮೆ RPM ನಿಯೋಜನೆಗಳಲ್ಲಿ ವಿನಂತಿ ಎಣಿಕೆಗಳು ಭವಿಷ್ಯಕ್ಕೆ ಕಂಡು ಹಿಡಿಯುವಂತೆ. ಪ್ರತಿಯೊಂದು ಇನ್ಫರೆನ್ಸ್ ವಿನಂತಿಗೆ 60 ಸೆಕೆಂಡು ಸಮಯ ಮಿತಿ ಇದೆ. ಟೋಕನ್ ಗಳ ಪಡೆಯಲು ಹೆಚ್ಚುವರಿ ಸಮಯ ಬೇಕಾಗಬಹುದು. ಅಪ್ಲಿಕೇಶನ್-ಮಟ್ಟದ ವೇಳಾಪಟ್ಟಿಯನ್ನು ಕೊಣಿಕೆಗಳನ್ನು ಗೌರವಿಸಿ; ವಿಫಲವಾದ ಪಾವತಿಸಿದ ವಿನಂತಿಯನ್ನು ಅವವಾಗಿ ಮರುನಡೆಸಬೇಡಿ.

## ಕ್ರಮಾನುಕ್ರಮ ಲೈವ್ ವರಿಫಿಕೇಶನ್

ಲೈವ್ ಕರೆಗಳು ಯೂನಿಟ್ ಪರೀಕ್ಷೆಗಳಿಂದ ಪ್ರತ್ಯೇಕವಾಗಿವೆ. ಕೆಳಗಿನ ಆಜ್ಞೆಗಳನ್ನು **ವೈಯಕ್ತಿಕವಾಗಿ**, ರೆಪೊ ರೂಟ್ ನಿಂದ ಮಾತ್ರ, ಪ್ರಮಾಣಪತ್ರಗಳು ಮತ್ತು ನಿಯೋಜನೆ ಪ್ರವೇಶ ಸಿದ್ಧವಾದ ನಂತರವೇ ಬಳಸಿ. ಯಾವುದೇ ಸೇವೆಗಳು ಅಥವಾ ಸ್ಥಿರ ಪ್ರಕ್ರಿಯೆಗಳ ಅಗತ್ಯವಿಲ್ಲ.

ಹಂಚಿಕೆಯ **10 ವಿನಂತಿಗಳು/ನಿಮಿಷ** ನಿಯೋಜನೆಗಾಗಿ, ಮುಂದಿನ ಪೂರ್ಣ ಪ್ರೋಗ್ರಾಮು ಆರಂಭಿಸುವ ಮುಂಚೆ ಸರಿಯಾದ ಪ್ರಮಾಣಿಕ ಕೊಣಿಕೆಗಳನ್ನು ಕಾಯ್ದಿರಿಸಿ: 5, 4, 1, ನಂತರ 6 ವಿನಂತಿಗಳು. ಕ್ರಮಾನುಕ್ರಮ ಪ್ರಕ್ರಿಯೆಗಳು ತಾನೇ ದರ-ನಿಯಮಕ ನಿಯಮ ಪಾಲನೆಯನ್ನು ಖಚಿತಪಡಿಸುವುದಿಲ್ಲ. ಎಲ್ಲಾ ಇತರ ಕರೆದಾರರೊಂದಿಗೆ ಪಾಲನೆಯ ಕಲ್ಲು ಕಟ್ಟಿಕೊಳ್ಳಿ; ನಾಲ್ಕನೇ ಕರೆಗಳನ್ನು ಉಂಟುಮಾಡದೇ ಬಳಗವಾಗಿ ನಕಲಿಸಬೇಡಿ.

```powershell
$env:AZURE_OPENAI_ENDPOINT = "https://your-resource.openai.azure.com/"
$env:AZURE_OPENAI_DEPLOYMENT = "gpt-5.6-luna"
$chapterPom = "03-CoreGenerativeAITechniques/examples/pom.xml"
```

**1. ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಗಳು, ಬಹುತಿರು, ಮತ್ತು ಎರಡು ಸಂವಾದಾತ್ಮಕ ತಿರುವುಗಳು:**

```powershell
"My name is Ada.`nWhat is my name?`nexit" | mvn -B -ntp -f $chapterPom compile exec:java "-Dexec.mainClass=com.example.genai.techniques.completions.LLMCompletionsApp"
```

ಎಲ್ಲಾ ಮೂರು ವಿಭಾಗ ಶೀರ್ಷಿಕೆಗಳು, ಐದು ಉತ್ತರಗಳು, ಅಡಾ ನೆನಪಿಸುವ ಅಂತಿಮ ಇಂಟರ್ಯಾಕ್ಟಿವ್ ಉತ್ತರ, `Goodbye!`, ಮತ್ತು ನಿರ್ಗಮನ ಕೋಡ್ 0 ಪರಿಶೀಲಿಸಿ. ಬಜೆಟ್: **5 ವಿನಂತಿಗಳು, ಗರಿಷ್ಠ 1,900 ಪೂರ್ಣಗೊಳಿಸುವ ಟೋಕನ್ಗಳು**. ಚಿಕ್ಕ ಓಟಕ್ಕೆ, ಕೇವಲ `exit` ಪೈಪ್ ಮಾಡಿ: 3 ವಿನಂತಿಗಳು / 900 ಟೋಕನ್ಗಳು, ಆದರೆ ಅದು ಇಂಟರ್ಯಾಕ್ಟಿವ್ ಇನ್ಫರೆನ್ಸ್ ಅನ್ನು ಪ್ರಯೋಗ ಮಾಡುತ್ತಿಲ್ಲ.

**2. ಎರಡೂ ಫಂಕ್ಷನ್-ಕಾಲ್ ವರ್ಕ್ಫ್ಲೋಗಳು:**

```powershell
mvn -B -ntp -f $chapterPom compile exec:java "-Dexec.mainClass=com.example.genai.techniques.functions.FunctionsApp"
```

ಎರಡು ಫಂಕ್ಷನ್ ಹೆಸರುಗಳು, ನಕಲಿ ಸಿಯಾಟಲ್ ಹವಾಮಾನ, ಲೆಕ್ಕಿಸಿದ ಫಲಿತಾಂಶ 36, ಎರಡು ಅಂತಿಮ ಉತ್ತರಗಳು, ಮತ್ತು ನಿರ್ಗಮನ ಕೋಡ್ 0 ಪರಿಶೀಲಿಸಿ. ಬಜೆಟ್: **4 ವಿನಂತಿಗಳು, ಗರಿಷ್ಠ 1,200 ಪೂರ್ಣಗೊಳಿಸುವ ಟೋಕನ್ಗಳು**.

**3. ದಾಖಲೆ-ಆಧಾರಿತ ಉತ್ತರ:**

```powershell
"Which authentication method does the document describe?" | mvn -B -ntp -f $chapterPom compile exec:java "-Dexec.mainClass=com.example.genai.techniques.rag.SimpleReaderDemo" "-Dexec.args=03-CoreGenerativeAITechniques/examples/document.txt"
```

ದಸ್ತಾವೇಜು ಪಥ, ಮೈಕ್ರೋಸಾಫ್ಟ್ ಎಂಟ್ರಾ ID ಅನ್ನು ಉಲ್ಲೇಖಿಸುವ ಉತ್ತರ ಮತ್ತು ನಿರ್ಗಮನ ಕೋಡ್ 0 ಪರಿಶೀಲಿಸಿ. ಬಜೆಟ್: **1 ವಿನಂತಿ, ಗರಿಷ್ಠ 500 ಪೂರ್ಣಗೊಳಿಸುವ ಟೋಕನ್ಗಳು**. ಇತ್ತೀಚಿನ [document.txt](../../../03-CoreGenerativeAITechniques/examples/document.txt) ಮಾತ್ರ ಅಗತ್ಯವಿರುವ ಒಳಗೊಳ್ಳುವ ಕಡತವಾಗಿದೆ. ಇಲ್ಲದ ವಿಷಯದ ಬಗ್ಗೆ ಕೇಳುವ ಐಚ್ಛಿಕ ಎರಡನೇ ಓಟವು ನಿರಾಕರಿಸಬೇಕು ಮತ್ತು ಅದು ಒಂದು ವಿನಂತಿ / 500 ಟೋಕನ್ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ.

**4. ಜವಾಬ್ದಾರಿಯುತ-ಎಐ ಗಮನಿಕೆಗಳು:**

```powershell
mvn -B -ntp -f $chapterPom compile exec:java "-Dexec.mainClass=com.example.genai.techniques.responsibleai.ResponsibleAIDemo"
```

ಆರು ವರ್ಗಗಳು ಮತ್ತು ಗಮನಿಕೆ ಸಾರಾಂಶ, ನಿರ್ಮಿತ ವಿಷಯ ಪರಿ, ಮತ್ತು ತಾಂತ್ರಿಕ ಪೂರ್ಣಗ್ರಹಣಕ್ಕೆ ನಿರ್ಗಮನ ಕೋಡ್ 0 ಅಗತ್ಯವಿದೆ ಪರಿಶೀಲಿಸಿ. ಯಶಸ್ವಿ ಪ್ರಕ್ರಿಯೆ ನಿರ್ಗಮನವು ಮಾದರಿ ಭದ್ರತೆ ಖಚಿತಪಡಿಸುವುದಿಲ್ಲ. ಬಜೆಟ್: **6 ವಿನಂತಿಗಳು, ಗರಿಷ್ಠ 1,800 ಪೂರ್ಣಗೊಳಿಸುವ ಟೋಕನ್ಗಳು**.

**ನಾಲ್ಕು ಆಜ್ಞೆಗಳ ಒಟ್ಟು: 16 ಚಾಟ್ ವಿನಂತಿಗಳು ಮತ್ತು ಗರಿಷ್ಠ 5,400 ಪೂರ್ಣಗೊಳಿಸುವ ಟೋಕನ್ಗಳು**, ಜೊತೆಗೆ ಇನ್‌ಪುಟ್ ಟೋಕನ್ಗಳು (ಪುನರಾವರ್ತಿತ ಸಂಭಾಷಣೆ ಮತ್ತು ಟೂಲ್ ಸ್ಕೀಮಾ/ಇತಿಹಾಸ ಸೇರಿ). ಒಬ್ಬರ embedding ವಿನಂತಿಗಳು ಇಲ್ಲ. ನೇರ ಟೋಕನ್ ಬಳಕೆ ಮಾದರಿಯ ಮೇಲೆ ಅವಲಂಬಿತವಾಗಿದ್ದು, ಕಡಿಮೆ ಇರಬಹುದು, ವಿಶೇಷವಾಗಿ ફિલ್ಟರ್ ಮಾಡಲಾದ ಪ್ರಾಂಪ್ಟ್ಗಳಿಗೆ. ಡಾಲರ್ ವೆಚ್ಚ ನಿಯೋಜನೆ ಬೆಲೆಗೆ ಅವಲಂಬಿತ; ನಿಗದಿತ ಹಣಕಾಸು ಅಂದಾಜು ಇಲ್ಲ. ಎಲ್ಲಾ ವಿನಂತಿ ಸೀಮೆಗಳು ಕೈಯಿಂದ ಪುನರಾವರ್ತನೆ ಇಲ್ಲದಂತೆ ধরেಕೊಳ್ಳಲಾಗಿದೆ. ಪ್ರತಿ ಆಜ್ಞೆಯ ನಂತರ ತಕ್ಷಣ `$LASTEXITCODE` ಪರಿಶೀಲಿಸಿ; ಶೂನ್ಯಕ್ಕಿಂತ ವ್ಯತ್ಯಾಸ ಇದ್ದರೆ ಓಟ ಯಶಸ್ವಿಯಾಗಿ ಪೂರ್ಣವಾಗಿಲ್ಲ ಅರ್ಥ.

## ಸಮಸ್ಯೆ ಪರಿಹಾರ

- **ಎಂಡ್ಪಾಯಿಂಟ್ ಕಾಣೆಯಾದ / 401 / 403:** ಪ್ರಾರಂಭಿಸುವ ಪ್ರಕ್ರಿಯೆಯಲ್ಲಿ ಎಂಡ್ಪಾಯಿಂಟ್ ಸೆಟ್ ಮಾಡಿರಿ, ನಿಮ್ಮ ಸ್ಥಳೀಯ ಅಜೆರ್ ಸೈನ್-ಇನ್ ಮತ್ತು ಸಂಪನ್ಮೂಲ-ಆಧಾರಿತ ಪಾತ್ರವನ್ನು ಪರಿಶೀಲಿಸಿ, ಮತ್ತು ಅನಗತ್ಯ ಗುರುತುಮಾಡುವ ಪರಿಸರ ಮೀರಿಸುವಿಕೆಯನ್ನು ತಪಾಸಣೆಮಾಡಿ.
- **400 / 404:** ನಿಯೋಜನೆ ಅಸ್ತಿತ್ವದಲ್ಲಿದೆ ಎಂದು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ ಮತ್ತು ಅಥೀನಾಗಿರುವ ಕಾರಣವಾಗಿರುವ ಚಾಟ್ ಪೂರ್ವಪೂರಣಗಳನ್ನು `none` ನಿರ್ದಿಷ್ಟತೆ ಜೊತೆಗೆ ಬೆಂಬಲಿಸುತ್ತದೆ. HTTPS ಸಂಪನ್ಮೂಲ ಮೂಲ ಅಥವಾ `/openai/v1` URL ಬಳಸಿರಿ, ಹಳೆ ನಿಯೋಜನೆ URL ಅಲ್ಲ. ಸಾಮಾನ್ಯ 400 ತಪ್ಪುಗಳು ತಾಂತ್ರಿಕ ವೈಫಲ್ಯಗಳು, ಭದ್ರತಾ ತಡೆಗಳು ಅಲ್ಲ.
- **429:** ಹಂಚಿಕೃತ RPM ಮತ್ತು ಟೋಕನ್ ಒತ್ತಡವನ್ನು ಸಂಯೋಜಿಸಿ ಮತ್ತೆ ಪ್ರಯತ್ನಿಸು. ಉದಾಹರಣೆಗಳು ಸ್ವಯಂಚಾಲಿತ ಪುನರ್ ಪ್ರಯತ್ನವನ್ನು ಮಾಡುತ್ತಿಲ್ಲ.
- **`ಅಧೂರು ಚಾಟ್ ಪ್ರತಿಕ್ರಿಯೆ: ಉದ್ದ`:** output ಪೂರ್ಣಗೊಳಿಸುವ ಮಿತಿಯನ್ನು ತಲುಪಿದೆ. ಮಿತಿಯನ್ನು ಮತ್ತು ಅದರ ದಾಖಲಾಗಿರುವ ಬಜೆಟ್ ಅನ್ನು ಹೆಚ್ಚಿಸುವ ಮೊದಲು ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಮತ್ತು ಪ್ರಾಂಪ್ಟ್ ಪರಿಶೀಲಿಸಿ; ತಪ್ಪಾಗಿ ಕಡಿತಗೊಂಡ ಓಟವನ್ನು ಯಶಸ್ವಿಯಾಗಿ ದಾಖಲಿಸಬೇಡಿ.
- **ಕಡತ ಅಥವಾ stdin ತಪ್ಪುಗಳು:** ಬೆಂಬಲಿತ ಡೈರೆಕ್ಟರಿಯಿಂದ ಪ್ರಾರಂಭಿಸಿ ಅಥವಾ ಸ್ಪಷ್ಟ ದಸ್ತಾವೇಜು ಪಥವನ್ನು ಪಾಸ್ ಮಾಡಿ. ಖಾಲಿ ಓದುಗುಳಿಕೆ ಪ್ರಶ್ನೆ ನೀಡಬೇಡಿ. ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಗಳು ಸಾಮಾನ್ಯವಾಗಿ EOF ಅಥವಾ `exit` ಮೇಲೆ ಸ್ವಾಭಾವಿಕವಾಗಿ ಮುಗಿಯಬಹುದು.
- **ಸಂಕಲನ ತಪ್ಪುಗಳು:** ಜावा 21 ಅಥವಾ ನಂತರದ ಆವೃತ್ತಿ ಪರಿಶೀಲಿಸಿ, ನಂತರ `mvn -B -ntp clean test` ಓಡು. ಪವರ್‌ಷೆಲ್‌ನಲ್ಲಿ, ಡಾಟ್‌ಗೊಂಡ ಗುಣಲಕ್ಷಣವನ್ನು ಒಳಗೊಂಡಿರುವ ಸಂಪೂರ್ಣ Maven ಯಾರುಮಾರ್ಗವನ್ನು ಉಲ್ಲೇಖಿಸಿ, ಉದಾಹರಣೆಗೆ `"-Dexec.mainClass=com.example.genai.techniques.functions.FunctionsApp"`.
