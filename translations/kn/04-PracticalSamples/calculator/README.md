## ನೀವು ಏನು ಕಲಿಯುವಿರಿ

ಈ ಟjúಟೋರಿಯಲ್ ಸುಧಾರಿತ ಕಾಂಟೆಕ್ಸ್ ಪ್ರೋಟೋಕಾಲ್ (MCP) ಬಳಸಿ ಕ್ಯಾಲ್ಕುಲೇಟರ್ ಸೇವೆಯನ್ನು ಏಕೆ ಮತ್ತು ಹೇಗೆ ನಿರ್ಮಿಸುವುದನ್ನು ವಿವರಿಸುತ್ತದೆ. ನೀವು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುತ್ತೀರಾ:

- ಹೇಗೆ AI ಒಂದು ಸಾಧನವಾದ ಸೇವೆಯನ್ನು ರಚಿಸುವುದು
- MCP ಸೇವೆಗಳೊಂದಿಗೆ ನೇರ ಸಂವಹನವನ್ನು ಹೇಗೆ ಹೊಂದಿಸಬೇಕು
- AI ಮಾದರಿಗಳು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಯಾವ ಸಾಧನಗಳನ್ನು ಬಳಸಬೇಕು ಎಂದು ಹೇಗೆ ಆರಿಸಿಕೊಳ್ಳುತ್ತವೆ
- ನೇರ ಪ್ರೋಟೋಕಾಲ್ ಕರೆ ಮತ್ತು AI ಸಹಾಯಿತ ಸಂವಹನದ ನಡುವಿನ ವ್ಯತ್ಯಾಸವನ್ನು

## ಆವಶ್ಯಕತೆಗಳು

ಪ್ರಾರಂಭಿಸುವ ಮೊದಲು, ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ ನೀವು ಹೊಂದಿದ್ದೀರಾ:
- ಜಾವಾ 21 ಅಥವಾ ಅದಕ್ಕೂ ಮೇಲಿನ ಆವೃತ್ತಿ ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಲಾಗಿದೆ
- ಆಶ್ರಿತತಾ ನಿರ್ವಹಣೆಗೆ ಮೇವನ್
- ಜಾವಾ ಮತ್ತು ಸ್ಪರಿಂಗ್ ಬೂಟ್ ಮೂಲಭೂತ ಅರಿವು

ಕೇವಲ AI ಕ್ಲೈಂಟ್ಗೆ ಮಾತ್ರ ಅಜುರ್ OpenAI ನಿಯೋಜನೆ ಮತ್ತು ಪರಿಶೀಲಿತ `DefaultAzureCredential` ಬೇಕಾಗುತ್ತದೆ,
ಉದಾಹರಣೆಗೆ ಸ್ಥಳೀಯವಾಗಿ ಇದ್ದ ಅಜುರ್ CLI ಸೈನ್-ಇನ್ ಅಥವಾ ಅಜುರ್‌ನಲ್ಲಿ ನೇರಿತ ಗುರುತಾಶಕ್ತಿ. ಗುರುತಾಶಕ್ತಿಗೆ
Cognitive Services OpenAI ಬಳಕೆದಾರ ಹಕ್ಕು ಬೇಕಾಗುತ್ತದೆ. [ಅಧ್ಯಾಯ 2](../../02-SetupDevEnvironment/getting-started-azure-openai.md) ನೋಡಿರಿ.
ಸರ್ವರ್, ನೇರ SDK ಕ್ಲೈಂಟ್, ಮತ್ತು ಎಲ್ಲಾ ಸ್ವಯಂಚಾಲಿತ ಪರೀಕ್ಷೆಗಳಿಗೆ ಅಜುರ್ ಖಾತೆ ಅಥವಾ ಮಾದರಿ ಪ್ರವೇಶ ಬೇಡ.

## ಪ್ರಮುಖ ಘಟಕಗಳು ವಿವರಣೆ

### 1. ಮುಖ್ಯ ಅಪ್ಲಿಕೇಶನ್

**ಫೈಲ್:** `McpServerApplication.java`

ಇದು ನಮ್ಮ ಕ್ಯಾಲ್ಕುಲೇಟರ್ ಸೇವೆಯ ಪ್ರವೇಶ ಬಿಂದು. ಇದು ಒಬ್ಬ ಸಾಮಾನ್ಯ ಸ್ಪರಿಂಗ್ ಬೂಟ್ ಅಪ್ಲಿಕೇಶನ್, ಒಂದು ವಿಶೇಷ ಸೇರ್ಪಡೆದೊಂದಿಗೆ:

```java
@SpringBootApplication
public class McpServerApplication {

    public static void main(String[] args) {
        SpringApplication.run(McpServerApplication.class, args);
    }
    
    @Bean
    public ToolCallbackProvider calculatorTools(CalculatorService calculator) {
        return MethodToolCallbackProvider.builder().toolObjects(calculator).build();
    }
}
```

**ಇದು ಏನು ಮಾಡುತ್ತದೆ:**
- 8080 ಪೋರ್ಟ್‌ನಲ್ಲಿ ಸ್ಪರಿಂಗ್ ಬೂಟ್ ವೆಬ್ ಸರ್ವರ್ ಪ್ರಾರಂಭಿಸಿ
- `ToolCallbackProvider` ಅನ್ನು ಸೃಷ್ಟಿಸಿ ಇದು ನಮ್ಮ ಕ್ಯಾಲ್ಕುಲೇಟರ್ ವಿಧಾನಗಳನ್ನು MCP ಸಾಧನಗಳಾಗಿ ಲಭ್ಯವಿಲ್ಲಿಸುತ್ತದೆ
- `@Bean` ಗುರುತು ಸ್ಪರಿಂಗ್‌ಗೆ ಇದನ್ನು ಉಪಕರಣವಾಗಿ ನಿರ್ವಹಿಸುವಂತೆ ಸೂಚಿಸುತ್ತದೆ, ಇದು ಇತರ ಭಾಗಗಳು ಬಳಸಬಹುದು

### 2. ಕ್ಯಾಲ್ಕುಲೇಟರ್ సేవೆ

**ಫೈಲ್:** `CalculatorService.java`

ಇಲ್ಲಿ ಎಲ್ಲಾ ಗಣಿತದ ಕಾರ್ಯಗಳು ನಡೆಯುತ್ತವೆ. ಪ್ರತಿ ವಿಧಾನವನ್ನು `@Tool` ಗುರುತಿನಿಂದ ಗುರುತಿಸಲಾಗಿದೆ, ಇದರಿಂದ MCP ಮೂಲಕ ಲಭ್ಯ:

```java
@Service
public class CalculatorService {

    @Tool(description = "Add two numbers together")
    public String add(double a, double b) {
        double result = a + b;
        return formatResult(a, "+", b, result);
    }

    @Tool(description = "Subtract the second number from the first number")
    public String subtract(double a, double b) {
        double result = a - b;
        return formatResult(a, "-", b, result);
    }
    
    // ಇನ್ನಷ್ಟು ಕ್ಯಾಲ್ಕುಲೇಟರ್ ಕಾರ್ಯಾಚರಣೆಗಳು...
    
    private String formatResult(double a, String operator, double b, double result) {
        return String.format(java.util.Locale.ROOT, "%.2f %s %.2f = %.2f", a, operator, b, result);
    }
}
```

**ಮುಖ್ಯ ವೈಶಿಷ್ಟ್ಯಗಳು:**

1. **`@Tool` ಗುರುತು**: ಇದು MCPಗೆ ಈ ವಿಧಾನವನ್ನು ಬಾಹ್ಯ ಕ್ಲೈಂಟ್ಗಳು ಕರೆ ಮಾಡಬಹುದು ಎಂದು ಸೂಚಿಸುತ್ತದೆ
2. **ಸ್ಪಷ್ಟ ವಿವರಣೆಗಳು**: ಪ್ರತಿ ಸಾಧನದ ವಿವರಣೆ ಇದನ್ನು ಯಾವಾಗ ಬಳಸಬೇಕು ಎಂಬುದನ್ನು AI ಮಾದರಿಗಳಿಗೆ ಸಹಾಯ ಮಾಡುತ್ತದೆ
3. **ಸ್ಥಿರ ಮರಳುವ ವಿನ್ಯಾಸ**:ಎಲ್ಲಾ ಕಾರ್ಯಗಳು "5.00 + 3.00 = 8.00" ಎಂಬ ಮಾನವ ಓದಲು ಸರಳ ಪಠ್ಯವನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತವೆ
4. **ದೋಷ ನಿರ್ವಹಣೆ**: ಶೂನ್ಯದಿಂದ ವಿಭಜನೆ ಮತ್ತು ಋಣಾತ್ಮಕ ವರ್ಗಮೂಲಗಳಿಗೆ ದೋಷ ಸಂದೇಶಗಳನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ

**ಲಭ್ಯವಿರುವ ಕಾರ್ಯಗಳು:**
- `add(a, b)` - ಎರಡು ಸಂಖ್ಯೆಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ
- `subtract(a, b)` - ಎರಡನೇ ಸಂಖ್ಯೆಯನ್ನು ಮೊದಲನೆಯಿಂದ ಕಡಿಮೆ ಮಾಡುತ್ತದೆ
- `multiply(a, b)` - ಎರಡು ಸಂಖ್ಯೆಗಳ ಗುಣಾಕಾರ
- `divide(a, b)` - ಮೊದಲನೆಯ ಸಂಖ್ಯೆಯನ್ನು ಎರಡನೆಯಿಂದ ವಿಭಾಗಿಸುತ್ತದೆ (ಶೂನ್ಯ ಪರಿಶೀಲನೆಯೊಂದಿಗೆ)
- `power(base, exponent)` - ಅಡಿಪಾಯವನ್ನು ಘಾತಾಂಕಕ್ಕೆ ವರ್ಧಿಸುತ್ತದೆ
- `squareRoot(number)` - ವರ್ಗಮೂಲವನ್ನು ಲೆಕ್ಕಿಸುತ್ತದೆ (ಋಣಾತ್ಮಕ ಪರಿಶೀಲನೆಯೊಂದಿಗೆ)
- `modulus(a, b)` - ವಿಭಾಗದ ಉಳಿಕೆಯನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ
- `absolute(number)` - ನಿರಪೇಕ್ಷ ಮೌಲ್ಯವನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ
- `help()` - ಎಲ್ಲಾ ಕಾರ್ಯಗಳ ಬಗ್ಗೆ ಮಾಹಿತಿಯನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ

### 3. ನೇರ MCP ಕ್ಲೈಂಟ್

ನೋಡಿ [SDKClient.java](../../../../04-PracticalSamples/calculator/src/test/java/com/microsoft/mcp/sample/client/SDKClient.java).

ಈ ಕ್ಲೈಯಿಂಟ್ `/mcp` ನಲ್ಲಿ `HttpClientStreamableHttpTransport` ಬಳಸುತ್ತದೆ, ಸಂಪರ್ಕ ಆರಂಭಿಸುತ್ತದೆ,
ಸರ್ವರ್ ಅನ್ನು ಪಿಂಗ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಸಾಧನ-ಪಟ್ಟಿ ಪುಟವರಿಗೆ ಅನುಸರಿಸುತ್ತದೆ. ಒಂಬತ್ತು ನಿರೀಕ್ಷಿತ ಸಾಧನಗಳಿದ್ದರೆ ಅದನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ
ಮತ್ತು ಪ್ರತಿಯೊಂದರಿಗೂ ಕರೆ ಮಾಡುತ್ತದೆ, `modulus` ಮತ್ತು `help` ಸಹಿತ, AI ಮಾದರಿ ಇಲ್ಲದೆ.

ಪ್ರಸ್ತುತ ವಿನಂತಿ ನಿರ್ಮಾಪಕ ಹೀಗೆ ಇರುತ್ತದೆ:

```java
var request = CallToolRequest.builder("add")
    .arguments(Map.of("a", 5.0, "b", 3.0))
    .build();
var result = client.callTool(request);
```

ಪ್ರೋಟೋಕಾಲ್ ದೋಷಗಳು ಕ್ಲೈಂಟ್‌ಗೆ ಅಯೋಗ್ಯ ವಿನಂತಿ ನೀಡಿ ಯಥಾರ್ಥ ಯಶಸ್ಸಿನನ್ನೂ ಮುದ್ರಿಸಲು ಬಿಡುವುದಿಲ್ಲ. MCP ಕ್ಲೈಂಟ್
try-with-resources ಮೂಲಕ ಮುಚ್ಚಲ್ಪಡುತ್ತದೆ, ಅನ್ವೇಷಣೆ ಅಥವಾ ಸಾಧನ ಕರೆ ವಿಫಲವಾದಾಗ ಸಹ.

`OpenAiOfficialChatModel` ಪ್ರಸ್ತುತ ಲಾಂಗ್‌ಚೈನ್4j `ChatModel` API ಅನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸುತ್ತದೆ.
`StreamableHttpMcpTransport` ಇದನ್ನು SDK ಕ್ಲೈಂಟ್ ಹಾಗೆ `/mcp` ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗೆ ಸಂಪರ್ಕಗೊಳಿಸುತ್ತದೆ.
`AiServices` ಸಾಧನಗಳನ್ನು ಅನ್ವೇಷಿಸಿ ಸಾಧನ-ಕರೆ/ಫಲಿತಾಂಶ ಸಂಭಾಷಣೆಯನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ.

ಡಿಫಾಲ್ಟ್ ನಿಯೋಜನೆ **GPT-5.6 Luna**, ಹೆಚ್ಚಿನ ವಿವೇಕವನ್ನು ನಿಷೇಧಿಸಲಾಗಿದೆ:

```java
var parameters = OpenAiOfficialChatRequestParameters.builder()
    .modelName("gpt-5.6-luna")
    .reasoningEffort("none")
    .maxCompletionTokens(1024)
    .parallelToolCalls(false)
    .build();
```

ಈ ಡಿಫಾಲ್ಟ್ ಪೂರೈಸುವುದನ್ನು ಪ್ರತಿಯೊಂದು ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಗೂ ಅನ್ವಯಿಸುತ್ತದೆ, ಸಾಧನ ಅನುಷ್ಟಾನದ ನಂತರವೂ ಸೇರಿ.
ಕ್ಲೈಂಟ್ `BearerTokenCredential` ಅನ್ನು `DefaultAzureCredential` ಬೆಂಬಲದೊಂದಿಗೆ ರಿಫ್ರೆಶ್ ಮಾಡಬಲ್ಲಂತೆ ಬಳಸುತ್ತದೆ
ಮತ್ತು `https://ai.azure.com/.default` ವ್ಯಾಪ್ತಿ, ಏಕಕಾಲಿಕ ಟೋಕನ್ ಅಲ್ಲ.
ಸಂಪನ್ಮೂಲ URL ಗಳನ್ನೂ ಮತ್ತು `/openai/v1` ನಲ್ಲಿ ಮುಕ್ತಾಯವಾಗುವ URL ಗಳನ್ನೂ ಸ್ವೀಕರಿಸುತ್ತದೆ.

ಬಾಟ್ ಮಾತೃಕ ಸಂಭಾಷಣೆ ಇಟ್ಟಿಡುತ್ತದೆ, `Tool executed: ...` ಅನ್ನು ವಾಸ್ತವ MCP ಫಲಿತಾಂಶದೊಂದಿಗೆ ಮುದ್ರಿಸುತ್ತದೆ,
ಮತ್ತು ಉತ್ತರ ಸಾಧನಗಳನ್ನು ಬಿಟ್ಟುಹೋಗಿದರೆ ವಿಫಲವಾಗುತ್ತದೆ. ಸಾಧನ ಲೂಪುಗಳು ನಾಲ್ಕು ಸುತ್ತುಗಳಷ್ಟಾಗಿವೆ.
ಪರಿಶೀಲನೆ, ಮಾದರಿ, MCP ಮತ್ತು ಸಾಧನ ದೋಷಗಳು ಪ್ರಸಾರವಾಗುತ್ತವೆ; ಸ್ವಯಂಚಾಲಿತ ಮಾದರಿ ಪునಃಪ್ರಯತ್ನ ನಿರ್ಬಂಧಿಸಲಾಗಿದೆ.
MCP ಸಾರಿಗೆ/ಕ್ಲೈಂಟ್ ಮತ್ತು ಅಧಿಕೃತ OpenAI ಕ್ಲೈಂಟ್ ಯಶಸ್ಸು ಅಥವಾ ವಿಫಲತೆಯ ಮೇಲೆ ಮುಚ್ಚಲಾಗುತ್ತದೆ.

## ಉದಾಹರಣೆಗಳು ರನ್ ಮಾಡುವುದು

### ಹಂತ 1: ಕಾಲ್ಕ್ಯುಲೇಟರ್ ಸರ್ವರ್ ಪ್ರಾರಂಭಿಸಿ

ಸರ್ವರ್‌ಗಾಗಿ ಯಾವುದೇ ಅಜೂರ್ ಸಂರಚನೆ ಅಗತ್ಯವಿಲ್ಲ. ಕೆಳಗಿನ ಕಮಾಂಡ್ಗಳು ಈ ಮಾದರಿಯ ಡೈರೆಕ್ಟರಿಯಿಂದ ದಾರಿತರುತ್ತವೆ.
مثال 18081 ಪೋರ್ಟ್ ಬಳಸುತ್ತದೆ, ಇನ್ನೊಂದು ಮಾದರಿಯೊಂದಿಗೆ ಸಂಧಾನAvoidಿಸುವುದಕ್ಕೆ; ಡೀಫಾಲ್ಟ್ 8080 ಆಗಿಯೇ ಉಳಿದಿದೆ.

```powershell
cd 04-PracticalSamples/calculator
mvn spring-boot:run "-Dspring-boot.run.arguments=--server.port=18081"
```

MCP ಎಂಡ್‌ಪಾಯಿಂಟ್‌ನ ಲಿಂಕ್ `http://localhost:18081/mcp`. ಆರೋಗ್ಯ ಮತ್ತು ಅನ್ವೇಷಣೆ ಮಾಹಿತಿ ಲಭ್ಯವಿವೆ
`http://localhost:18081/health` ಮತ್ತು `http://localhost:18081/info` ನಲ್ಲಿ.
ಸ್ಟ್ರೀಮಬಲ್ HTTP ಹಳೆಯ SSE-ಮಾತ್ರ ಸಂಚಾರದ ಪೂರಕ; `/sse` ಮತ್ತು `/v1/tools` ಎಂಡ್‌ಪಾಯಿಂಟ್ ಗಳು ಅಲ್ಲ.

### ಹಂತ 2: ನೇರ ಕ್ಲೈಂಟ್‌ನೊಂದಿಗೆ ಪರೀಕ್ಷಿಸಿ

ಮತ್ತೊಂದು ಪವರ್‌ಶೆಲ್ ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ:

```powershell
cd 04-PracticalSamples/calculator
$env:MCP_SERVER_URL = "http://localhost:18081"
mvn test-compile exec:java "-Dexec.mainClass=com.microsoft.mcp.sample.client.SDKClient" "-Dexec.classpathScope=test"
```

ಯಾವುದೇ ಇನ್‌ಪುಟ್ ಅಗತ್ಯವಿಲ್ಲ. ಎಲ್ಲಾ ಒಂಬತ್ತು ಉಪಕರಣಗಳು ಕಾರ್ಯಗತವಾಗುತ್ತವೆ. ನಿರೀಕ್ಷಿತ ಗಣಿತ ಫಲಿತಾಂಶಗಳೆಂದರೆ
8, 6, 42, 5, 256, 4, 2, ಮತ್ತು 5.5, ನಂತರ ಸಹಾಯ ಪಠ್ಯ.

### ಹಂತ 3: AI ಕ್ಲೈಂಟ್‌ನೊಂದಿಗೆ ಪರೀಕ್ಷಿಸಿ

ಪೂರ್ವಾಪೇಕ್ಷೆಗಳಲ್ಲಿ ವಿವರಿಸಿದಂತೆ ಮಾನ್ಯತೆಯನ್ನು ಪಡೆದ ನಂತರ, ಅದೇ ಟರ್ಮಿನಲ್‌ನಲ್ಲಿ AI ಕ್ಲೈಂಟ್ ಅನ್ನು ಸಂರಚಿಸಿ:

```powershell
$env:AZURE_OPENAI_ENDPOINT = "https://your-resource.openai.azure.com/"
$env:AZURE_OPENAI_DEPLOYMENT = "gpt-5.6-luna"
mvn test-compile exec:java "-Dexec.mainClass=com.microsoft.mcp.sample.client.LangChain4jClient" "-Dexec.classpathScope=test" "-Dexec.args=--prompt 'Calculate the sum of 24.5 and 17.3 using the calculator service'"
```

`Tool executed: add` ಅಂದ್ರೆ 41.80 ರೇಖೆಯನ್ನು ನಿರೀಕ್ಷಿಸಿ, ನಂತರ ಮಾದರಿಯ ಉತ್ತರ.
ಸಿಂಗಲ್-ಪ್ರಾಂಪ್ಟ್ ಮೋಡ್ ಇನ್‌ಪುಟ್ಿಗಾಗಿ ಕಾಯದೆ ನಿಂತುತ್ತದೆ. ಮೂಲ ನಾಲ್ಕು-ಪ್ರಾಂಪ್ಟ್ ಡೆಮೋ ಕಾರ್ಯಗತಗೊಳಿಸಲು:

```powershell
mvn test-compile exec:java "-Dexec.mainClass=com.microsoft.mcp.sample.client.LangChain4jClient" "-Dexec.classpathScope=test" "-Dexec.args=--demo"
```

ಡೆಮೋವು `add`, `squareRoot`, `help`, ಮತ್ತು ಸರಪಳಿ `power` ನಂತರ `divide` ಕಾರ್ಯವನ್ನು ಕರೆಯುತ್ತದೆ.
ನಿರೀಕ್ಷಿತ ಸಂಖ್ಯಾತ್ಮಕ ಉತ್ತರಗಳೆಂದರೆ 41.8, 12, ಮತ್ತು 64. ಆಯ್ಕೆಯನ್ನು ಬಿಟ್ಟು ಹಾಕಿದರೂ ಈ ಡೆಮೋ ನಡೆಯುತ್ತದೆ.

### ಹಂತ 4: ಪರಸ್ಪರ ಕ್ರಿಯಾಶೀಲ ಬಾಟ್ ಚಾಲನೆ

```powershell
mvn test-compile exec:java "-Dexec.mainClass=com.microsoft.mcp.sample.client.Bot" "-Dexec.classpathScope=test"
```

`Multiply 6 by 7 using the calculator service` ನಮೂದಿಸಿ, ನಂತರ `exit` ಅಥವಾ `quit` ಟೈಪ್ ಮಾಡಿರಿ.
ನಿಜವಾದ `multiply` ಉಪಕರಣ ಫಲಿತಾಂಶ 42 ಎಂದು ನಿರೀಕ್ಷಿಸಿ. ಖಾಲಿ ಸಾಲುಗಳನ್ನು ನಿರ್ಲಕ್ಷಿಸಿ; EOF ಕೂಡಾ ಸೆಷನ್ ನ್ನು ಮುಗಿಸುತ್ತದೆ.
ಈ ಎಂಟ್ರಿಪಾಯಿಂಟ್‌ನ ಅನ್‌ಇಂಟರಾಕ್ಟಿವ್ ಸ್ಮೋಕ್ ಟೆಸ್ಟ್ ಕೈಗೆಟುಕುವಷ್ಟಾಗುವುದೆಂದರೆ:

```powershell
mvn test-compile exec:java "-Dexec.mainClass=com.microsoft.mcp.sample.client.Bot" "-Dexec.classpathScope=test" "-Dexec.args=--prompt 'Multiply 6 by 7 using the calculator service'"
```

ಎರಡೂ AI ಎಂಟ್ರಿಪಾಯಿಂಟ್‌ಗಳು `--prompt "question"`, `--demo`, ಮತ್ತು `--interactive` ವನ್ನು ಸ್ವೀಕರಿಸುತ್ತವೆ.
ಅಕ್ರಮ ಆಯ್ಕೆಗಳು ಸಂಪರ್ಕ ತೆರೆದಿಡುವುದಕ್ಕೂ ಮುನ್ನ ವಿಫಲವಾಗುತ್ತವೆ. ಪ್ರತಿ Maven `-D...` ಪರಾಮರ್ಶೆಯನ್ನು ಪವರ್‌ಶೆಲ್‌ಗೆ ಪೂರ್ಣವಾಗಿ ಉಲ್ಲೇಖಿಸಿ
ಬಾಶ್‌ನಲ್ಲಿ `$env:NAME = "value"` ಬದಲು `export NAME=value` ಬಳಸಿ.

**ಕ್ವೋಟಾ:** AI ಮಾದರಿಗಳನ್ನು ಕ್ರಮವಾಗಿ ಚಲಾಯಿಸಿ. ಸರಳ ಪ್ರಾಂಪ್ಟ್ ಸಾಮಾನ್ಯವಾಗಿ ಎರಡು ಮಾದರಿ ವಿನಂತಿಗಳನ್ನು ಬೇಕಾಗಿರುತ್ತದೆ;
ಸಂಪೂರ್ಣ ಡೆಮೋ ಸಾಮಾನ್ಯವಾಗಿ ಒಂಬತ್ತು ವಿನಂತಿಗಳನ್ನು ಒಳಗೊಂಡಿದೆ, ಉಪಕರಣ ಫಲಿತಾಂಶ ಅನುಕ್ರಮಗಳನ್ನು ಸೇರಿಸಿ. ಹಂಚಿಕೆಯ 10 RPM
ನಿಯೋಜನೆಯಲ್ಲಿ, ಮುಂದಿನ AI ಚಲನೆಯ ಮೊದಲು ಹೊಸ ಕ್ವೋಟಾ ವಿಂಡೋ ಕಾತರಿಸಬೇಕು. 429 ಕಾಣಿಸಿಕೊಳ್ಳುವಂತೆ ವಿಫಲವೋ ಆತನ ಮರುಪ್ರಯತ್ನಗಳಿಲ್ಲದೇ;
ಸೇವೆಯ ಮರುಪ್ರಯತ್ನ ಮಾರ್ಗಸೂಚಿಯನ್ನು ಅನುಸರಿಸಿ. ನಿಜವಾದ ವಿನಂತಿ ಎಣಿಕೆಯನ್ನು ಮಾದರಿ ನಿರ್ಧರಿಸುತ್ತದೆ.
ಆಫ್‌ಲೈನ್ ಪರೀಕ್ಷೆಗಳು ಯಾವುದೇ ಕ್ವೋಟಾ ಬಳವು ಮಾಡದು ಮತ್ತು ಲೈವ್ ಲুনಾ ಲಭ್ಯತೆ ಅಥವಾ ಉತ್ತರ ಗುಣಮಟ್ಟವನ್ನು ಸ್ಥಾಪಿಸುವುದಿಲ್ಲ.

### ಸಂರಚನೆ ಮತ್ತು ಶಟ್ಡೌನ್

| ಸೆಟ್ಟಿಂಗ್ | ಡೀಫಾಲ್ಟ್ / ನಡೆ |
| --- | --- |
| `MCP_SERVER_URL` | `http://localhost:8080`; ಮೂಲ URL, `/mcp` ಹೊರತೆಗೆಯದೆ |
| `-Dmcp.server.url=...` | ಎಲ್ಲಾ ಕ್ಲೈಂಟ್‌ಗಳಿಗೂ `MCP_SERVER_URL` ಅನ್ನು ಮೀರಿಸುವುದು |
| `AZURE_OPENAI_ENDPOINT` | AI ಕ್ಲೈಂಟ್‌ಗಳಿಗೆ ಮಾತ್ರ ಅಗತ್ಯ; ರಿಸೋರ್ಸ್ URL ಅಥವಾ `/openai/v1` URL |
| `AZURE_OPENAI_DEPLOYMENT` | `gpt-5.6-luna`; ಅಜೂರ್ ನಿಯೋಜನೆಯ ಹೆಸರು |
| `AZURE_OPENAI_MAX_COMPLETION_TOKENS` | `1024`; ಧನಾತ್ಮಕ ಪೂರ್ಣಾಂಕ |
| ಯುಕ್ತಿಭೂತ ಪ್ರಯತ್ನ | ಯಾವಾಗಲೂ `none`, ಒಳಗೊಂಡಿರುವ ಉಪಕರಣ-ಲೂಪ್ പിന്തുടರಿಕೆಗಳ ಸಹಿತ |

ಮೀರಿಸಲ್ಪಟ್ಟ ನಿಯೋಜನೆಗೆ `reasoning_effort=none` ಮತ್ತು `max_completion_tokens` ಅನ್ನು ಬೆಂಬಲಿಸುವುದು ಅಗತ್ಯ.
ಕ್ಲೈಯಂಟ್ಗಳು ಸ್ವಯಂಚಾಲಿತವಾಗಿ `.env` ಫೈಲ್ ಓದುವುದಿಲ್ಲ. ಪರೀಕ್ಷೆಯ ನಂತರ ಸರ್ವರ್ ಅನ್ನು `Ctrl+C` ಮೂಲಕ ನಿಲ್ಲಿಸಿ.
ಕ್ಲೈಯಂಟ್ಗಳು ಸಾಮಾನ್ಯವಾಗಿ `System.exit` ಅಥವಾ ಶಟ್ಡೌನ್ ಸ್ಲೀಪ್‌ಗಳಿಲ್ಲದೆ ಹಿಂದಿರುಗುತ್ತವೆ.

## ಆಫ್‌ಲೈನ್ ಪರೀಕ್ಷೆಗಳು

```powershell
mvn -B -ntp clean verify
```

ಎಲ್ಲಾ ಪರೀಕ್ಷೆಗಳು Azure ನ ದೃಷ್ಟಿಕೋನದಿಂದ ಆಫ್‌ಲೈನ್: ಪ್ರೋಟೋಕಾಲ್ ಸೂಟ್ ಸ್ಪ್ರಿಂಗ್ ಸರ್ವರ್ ಮತ್ತು
ಓಪನ್‌ಎಐ-ಅನುಕೂಲಿತ ಸ್ಟಬ್ ಅನ್ನು ರ್ಯಾಂಡಂ ಲೂಪ್‌ಬ್ಯಾಕ್ ಪೋರ್ಟ್ಗಳಲ್ಲಿ ಪ್ರಾರಂಭಿಸಿ, ನಂತರ ಅವುಗಳನ್ನು ಮುಚ್ಚುತ್ತದೆ. ಮೇವನ್ ಇನ್ನೂ ಅವಲಂಬನೆಗಳನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಬೇಕಾಗಬಹುದು.
ಯಾವುದೇ ಮಾನ್ಯಪತ್ರಗಳು, ಲೈವ್ ನಿಯೋಜನೆ, ಅಥವಾ ಪೂರ್ವ-ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ MCP ಸರ್ವರ್ ಬಳಸಲಾಗುವುದಿಲ್ಲ.

- ಕ್ಯಾಲ್ಕ್ಯುಲೇಟರ್ ಯೂನಿಟ್ ಪರೀಕ್ಷೆಗಳು ಎಲ್ಲಾ ಅಂಕಗಣಿತ ಕಾರ್ಯಾಚರಣೆಗಳನ್ನು, ದಶಮಲವ ಫಲಿತಾಂಶಗಳನ್ನು, ಸಹಾಯ ಮತ್ತು ಡೊಮೇನ್ ದೋಷಗಳನ್ನು ವ್ಯಾಪಿಸುತ್ತವೆ.
- MCP ಪರೀಕ್ಷೆಗಳು ಪ್ರಾರಂಭ, ಪತ್ತೆ, ಎಲ್ಲಾ ಒಂಬತ್ತು ಉಪಕರಣ ಕರೆಗಳನ್ನು, ಉಪಕರಣ ವೈಫಲ್ಯಗಳನ್ನು ಮತ್ತು ಆರೋಗ್ಯ/ಮಾಹಿತಿಗಳನ್ನು ವ್ಯಾಪಿಸುತ್ತವೆ.
- AI ಪ್ರೋಟೋಕಾಲ್ ಪರೀಕ್ಷೆಗಳು ಪೂರ್ಣ ಡೆಮೊ ಮತ್ತು ಸಂವಾದ ಬಾಟ್ ಅನ್ನು ನಿಜವಾದ ಕ್ಯಾಲ್ಕ್ಯುಲೇಟರ್ ವಿರುದ್ಧ ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತವೆ,
  ಉಪಕರಣ ಫಲಿತಾಂಶಗಳು ಮುಂದಿನ ಪೂರ್ಣತೆಗೆ ಆಹಾರ ತುಂಬುತ್ತವೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ, ಮತ್ತು Luna ನ ಪ್ರತಿಯೊಂದೂ HTTP ಬಾಡಿಯನ್ನು ಪರಿಶೀಲಿಸುತ್ತವೆ,
  `reasoning_effort: "none"` ಮತ್ತು `max_completion_tokens` ಅನ್ನು ಎಳೆಯಿಂಗ್ ಷರತ್ತುಗಳಿಲ್ಲದ `max_tokens` ಜೊತೆಗೆ,
- ನಿರ್ವಹಣೆ/ಇನ್ಪುಟ್ ಪರೀಕ್ಷೆಗಳು ನಿಯೋಜನೆ ಮತ್ತು ಎಂಡ್ಪಾಯಿಂಟ್ ಮೀರಿಸಲು, ಖಾಲಿ ಸಾಲುಗಳು, EOF, ನಿರ್ಗಮನ/ನಿರ್ಗಮನ,
  ಏಕ-ಪ್ರಾಂಪ್ಟ್ ಮೋಡ್, ಅಮಾನ್ಯ ಆಯ್ಕೆಗಳು ಮತ್ತು ದೋಷ ಹರಡುವಿಕೆಗಳನ್ನು ವ್ಯಾಪಿಸುತ್ತವೆ. ಕೊಟಾ ಪರೀಕ್ಷೆಗಳು 429 ಮರುಪ್ರಯತ್ನಿಸಲಾಗುವುದಿಲ್ಲ ಎಂದು ತೋರಿಸುತ್ತವೆ.

## ಇದು ಎಲ್ಲವು ಹೇಗೆ ಒಟ್ಟಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ

ನೀವು AIಿಗೆ "5 + 3 ಎಷ್ಟು?" ಎಂದು ಕೇಳುವಾಗ ಸಂಪೂರ್ಣ ಪ್ರಕ್ರಿಯೆಯು ಇಲ್ಲಿದೆ:

1. **ನೀವು** AIಗೆ ಸಹಜ ಭಾಷೆಯಲ್ಲಿ ಕೇಳುತ್ತೀರಿ
2. **AI** ನಿಮ್ಮ ವಿನಂತಿಯನ್ನು ವಿಶ್ಲೇಷಿಸಿ ನೀವು ಸೇರಿಸುವಿಕೆ ಬೇಕಾಗಿರುವುದನ್ನು ಅರಿಯುತ್ತದೆ
3. **AI** MCP ಸರ್ವರ್ ಅನ್ನು ಕರೆಮಾಡುತ್ತದೆ: `add(5.0, 3.0)`
4. **ಕ್ಯಾಲ್ಕ್ಯುಲೇಟರ್ ಸೇವೆ** ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತದೆ: `5.0 + 3.0 = 8.0`
5. **ಕ್ಯಾಲ್ಕ್ಯುಲೇಟರ್ ಸೇವೆ** ಹಿಂತಿರುಗಿಸುತ್ತದೆ: `"5.00 + 3.00 = 8.00"`
6. **AI** ಫಲಿತಾಂಶವನ್ನು ಸ್ವೀಕರಿಸಿ ಸಹಜ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ರೂಪಿಸುತ್ತದೆ
7. **ನೀವು** ಪಡೆಯುತ್ತೀರಿ: "5 ಮತ್ತು 3ರ ಮೊತ್ತವು 8 ಆಗಿದೆ"
