# Учебник за Foundry Local Spring Boot

Стартирайте малък езиков модел на собствената си машина и извикайте неговия OpenAI-съвместим
REST крайна точка от Java конзолно приложение. Не се използва Azure разгръщане, Azure влизане,
ключ за облачен API или облачно извеждане. **GPT-5.6 Luna е само за Azure; не го
конфигурирайте като Foundry Local модел.**

## Версии и предпоставки

| Компонент | Версия |
| --- | --- |
| Java | 21 или по-нова |
| Maven | 3.6.3 или по-нова |
| Spring Boot | 4.1.1 |
| OpenAI Java SDK | 4.63.1 |
| Foundry Local SDK (локален REST сървър) | 2.0.1 |
| Node.js (локален REST сървър) | 20 или по-нова |
| Foundry Local CLI (по избор, отделно издание) | 0.10.3 preview |

Spring Boot управлява версиите на Spring Framework, Jackson, JUnit и Maven плъгини.
Този пример използва директно OpenAI Java SDK, а не Spring AI. Старата неизползвана
Spring AI milestone опция и хранилище са премахнати.

Препоръчваният стартов модел е **Qwen 2.5 0.5B**, CPU вариант
`qwen2.5-0.5b-instruct-generic-cpu:4` (приблизително 822 MB в каталога).
Той избягва изискванията за GPU изпълнителни доставчици. Други поддържани, кеширани малки модели
могат да бъдат избрани експлицитно. Инсталацията на модел и време за изпълнение изисква достъп до мрежа;
подсказките и извеждането остават локални. Foundry Local може все пак да генерира минимални диагностични
съобщения за време на изпълнение дори и с изключена несъществена телеметрия.

Стартирайте следните команди от тази примерна директория.

## Компилиране и тест на Java

```powershell
mvn clean verify
```

HTTP договорните тестове стартират временен loopback сървър и тестват реалния
OpenAI Java SDK. Те обхващат сериализация на заявки, откриване на модели, експлицитен избор на модел,
двусмислени или неправилни списъци с модели, HTTP повреди, празни отговори,
локални URL адреси и предаване на грешки от командния ред. Не изискват модел или
мрежов достъп отвъд инсталация на Maven зависимости. Живият тест е с опция за включване.

## Стартиране на локалния модел

### Препоръчително: фиксиран SDK сървър

Няма нативен Foundry Local Java SDK. Малкият Node.js помощник хоства
официалния SDK REST сървър; заявката към приложението и чата остава Java.

Инсталирайте фиксираните зависимости за време на изпълнение:

```powershell
npm ci
```

Ако Windows x64 не може да достигне NuGet по време на нативната инсталация на SDK, използвайте предоставения
резервен вариант. Той изтегля съответния официален GitHub архив за време на изпълнение, проверява
SHA-256 хеш на изданието и разполага DLL файловете до нативния аддон. Не
изключва TLS валидация, не изисква повишени права и не модифицира изходния код на SDK.

```powershell
npm ci --ignore-scripts
pwsh -File ./scripts/install-foundry-runtime.ps1
```

Изброяване на вече кешираните модели на тази машина:

```powershell
npm run start:foundry -- --list
```

При първоначално стартиране, изрично разрешете изтеглянето на малкия CPU модел:

```powershell
npm run start:foundry -- --model qwen2.5-0.5b-instruct-generic-cpu:4 --download --port 5273
```

При следващи стартирания, пропуснете `--download`, за да изисквате кеширан модел:

```powershell
npm run start:foundry -- --model qwen2.5-0.5b-instruct-generic-cpu:4 --port 5273
```

Помощникът предпочита съответстващ кеширан модел, приема псевдоним или точен ID на вариант,
и отказва липсващ модел, освен ако не е подаден `--download`. Регистрирa само
изпълнителния доставчик на избрания модел, когато е необходим. Кешираните GPU варианти все още могат
да изискват съвместими пакети за изпълнителен доставчик и драйвери.

Ако порт 5273 е зает, подайте `--port 0` за наличен порт. Помощникът отпечатва
`FOUNDRY_LOCAL_BASE_URL`, точния `FOUNDRY_LOCAL_MODEL` ID и PID, когато е готов.
Използвайте отпечатаната крайна точка в Java. Оставете тази терминална сесия отворена докато стартирате Java;
**Ctrl+C** спира REST сървъра и освобождава модела.

По подразбиране кешът е `~/.foundry/cache/models`. Задайте `FOUNDRY_LOCAL_CACHE_DIR` за
различен съществуващ кеш. Логове и състояние на помощника се записват в поддиректорията
`target/foundry-local` на този пример. Спрете помощника преди да стартирате `mvn clean`.

### По избор: Foundry Local CLI

CLI и SDK имат независими издания: CLI **0.10.3** включва SDK **1.2.4**;
горният помощник използва SDK **2.0.1**. Инсталирането на най-новия CLI не инсталира
най-новия езиков SDK. Вижте [бележки по изданието на CLI](https://github.com/microsoft/Foundry-Local/releases/tag/cli-preview-0.10.3).

В Windows използвайте командата за инсталация за потребителя ако CLI липсва:

```powershell
winget install --id Microsoft.FoundryLocal --exact --source winget --scope user --silent --accept-package-agreements --accept-source-agreements --disable-interactivity
```

Или обновете съществуваща инсталация:

```powershell
winget upgrade --id Microsoft.FoundryLocal --exact --source winget --scope user --silent --accept-package-agreements --accept-source-agreements --disable-interactivity
foundry --version
```

CLI 0.10.x замества старите команди `foundry service` с `foundry server`:

```powershell
foundry server start --port 5273
foundry cache list
foundry model load qwen2.5-0.5b-instruct-generic-cpu:4
foundry server status --output json
```

`model load` изисква вече изтеглен модел. Проверете `foundry model --help` за
командите за изтегляне. Използвайте реалната крайна точка от изхода на статуса; CLI по подразбиране
избира автоматично порт. Не стартирайте CLI и SDK помощник
на един и същи порт. Когато приключите:

```powershell
foundry server stop
```

## Стартирайте Java приложението

Втора терминална сесия, задайте крайната точка и точния модел ID, отпечатани от вашия сървър:

```powershell
$env:FOUNDRY_LOCAL_BASE_URL = "http://127.0.0.1:5273/v1"
$env:FOUNDRY_LOCAL_MODEL = "qwen2.5-0.5b-instruct-generic-cpu:4"
mvn spring-boot:run
```

Или стартирайте пакетираното приложение:

```powershell
java -jar target/foundry-local-spring-boot-0.0.1-SNAPSHOT.jar
```

Единствената Java входна точка е `com.example.Application`. Тя отпечатва избраната
крайна точка, реалния модел ID, подсказката и генерирания отговор, след което затваря Spring
контекста и HTTP клиента. Неуспешното извеждане или липсващ текст на отговора генерира
грешно приключване вместо успешно с форма на заместител.

### Конфигурация

| Променлива на средата | По подразбиране | Цел |
| --- | --- | --- |
| `FOUNDRY_LOCAL_BASE_URL` | `http://127.0.0.1:5273/v1` | Loopback HTTP крайна точка, включително `/v1` |
| `FOUNDRY_LOCAL_MODEL` | Празно | Точен ID на модел; иначе избира единичния рекламиран модел |
| `FOUNDRY_LOCAL_PROMPT` | Въпрос в едно изречение за локалните модели | Подсказка изпратена от конзолния стартиращ |

Еквивалентни Spring аргументи са `--foundry.local.base-url=...`,
`--foundry.local.model=...` и `--foundry.local.prompt=...`.
Приемат се само loopback HTTP крайни точки. Отдалечени/облачни крайни точки, вградени
идентификационни данни, низове за заявки и пътища без `/v1` се отхвърлят.

Празната настройка на модел работи само когато `/v1/models` рекламира точно един модел.
Рекламираният модел не задължително е зареден. Ако са рекламирани множество модели,
задайте точния зареден ID, вместо да разчитате на подредбата в каталога.

Заявките използват `temperature=0`, ограничение на изхода от 150 токена, таймаут от 120 секунди и
няма автоматични повторни опити. Полето за заявка `max_tokens` е умишлено: то е
поддържано от REST договора на Foundry Local, въпреки че OpenAI Java го обезкуражава
това поле за по-нови облачни модели. Идентичността на модела идва от конфигурация или
откриване, а не от твърденията на модела за себе си.

## Живо валидиране

С работещ локален сървър, изпълнете всички тестове, включително избираемия жив тест.
Заменете порта на крайния пункт със стойността, отпечатана от вашия сървър. Цитирайте точковите
свойства на Maven в PowerShell:

```powershell
mvn "-Dfoundry.local.live=true" "-Dfoundry.local.base-url=http://127.0.0.1:5273/v1" "-Dfoundry.local.model=qwen2.5-0.5b-instruct-generic-cpu:4" verify
```

Живият тест извиква `Application.main`, предоставя факта "Столицата на
Франция е Париж," иска града и проверява дали реално генерираният текст е
`Paris`. Проверява се семантичният резултат, не само успешният HTTP статус.

Това е интеграционна проверка, а не тест за точност. По време на валидирането,
моделът 0.5B отговори на отделно подаден "2 + 2" с `3` както през Java, така и през директно
REST. Не разчитайте на него за аритметична или фактологична точност без независима
проверка; използвайте детерминирани инструменти за изчисления.

## Отстраняване на проблеми

| Симптом | Проверка |
| --- | --- |
| Връзката отказана | Изчакайте съобщението за готовност; използвайте отпечатания порт и пътя `/v1`. |
| Рекламирани са множество модели | Задайте `FOUNDRY_LOCAL_MODEL` на точния идентификатор на заредения модел. |
| Липсва модел | Използвайте `--list` или изрично позволете сваляне с `--download`. |
| Доставчикът на GPU се проваля или заема време | Използвайте малкия CPU модел. Кеширан GPU модел все още се нуждае от доставчика си. |
| CLI остава в състояние `initializing` | Прочетете `foundry server logs --lines 80`; спрете демона и използвайте помощника на SDK. |
| Неуспех при TLS/сваляне на NuGet | Поправете мрежовия достъп или използвайте проверения горе Windows x64 резервен вариант. Не деактивирайте TLS. |
| Портът е зает | Използвайте `--port 0` и конфигурирайте Java с отпечатания крайна точка. |
| Няма избори или празен текст | Приложението умишлено се проваля; проверете модела и логовете на runtime. |
