# Посібник для початківців зі створення історій про домашніх улюбленців

Завантажте фото домашнього улюбленця, проаналізуйте його за допомогою GPT-5.6 Luna та згенеруйте історію на основі отриманого опису. Обидва запити моделі використовують `reasoning_effort: none`.

| Компонент | Версія |
| --- | --- |
| Java | 21 або вище |
| Spring Boot | 4.1.1 |
| OpenAI Java SDK | 4.63.1 |
| Azure Identity | 1.18.6 |

## Вимоги

Перед початком переконайтесь, що у вас є:
- Встановлена Java 21 або новіша
- Maven для керування залежностями
- Розгортання Azure AI Foundry GPT-5.6 Luna з ім’ям `gpt-5.6-luna` або перевизначення `AZURE_OPENAI_DEPLOYMENT`, яке вказує на це розгортання. Дивіться [Розділ 2](../../02-SetupDevEnvironment/getting-started-azure-openai.md) для налаштування та увійдіть за допомогою `az login` для автентифікації без ключів. Розгортання повинно підтримувати введення зображень та `reasoning_effort: none`.
- Базове розуміння Java, Spring Boot та веб-розробки

## Розуміння структури проєкту

Проєкт історій про домашніх улюбленців має кілька важливих файлів:

```
petstory/
├── src/main/java/com/example/petstory/
│   ├── PetStoryApplication.java       # Main Spring Boot application
│   ├── PetController.java             # Web request handler
│   ├── StoryService.java              # AI image analysis and story generation
│   └── SecurityConfig.java            # Security configuration
├── src/main/resources/
│   ├── application.properties         # App configuration
│   └── templates/
│       ├── index.html                 # Upload form page
│       └── result.html               # Story display page
└── pom.xml                           # Maven dependencies
```

## Пояснення основних компонентів

### 1. Головна програма

**Файл:** `PetStoryApplication.java`

Це точка входу для нашої Spring Boot програми:

```java
@SpringBootApplication
public class PetStoryApplication {
    public static void main(String[] args) {
        SpringApplication.run(PetStoryApplication.class, args);
    }
}
```

**Що це робить:**
- Анотація `@SpringBootApplication` увімкне авто-конфігурацію та пошук компонентів
- Запускає вбудований веб-сервер (Tomcat) на порту 8080
- Автоматично створює всі необхідні Spring біні та сервіси

### 2. Веб-контролер

**Файл:** [PetController.java](../../../../04-PracticalSamples/petstory/src/main/java/com/example/petstory/PetController.java)

| Ендпоінт | Запит | Успішна відповідь |
| --- | --- | --- |
| `GET /` | Без тіла | HTML-форма завантаження із CSRF токеном |
| `POST /analyze-image` | `multipart/form-data`, поле файлу `image` | JSON: `{"description":"Грайливий улюбленець..."}` |
| `POST /generate-story` | `application/x-www-form-urlencoded`, поле `description` | HTML-сторінка з результатом, що містить опис та згенеровану історію |

Обидва POST ендпоінти вимагають cookie сесії та CSRF токен, отримані із `GET /`. Скрипт завантаження надсилає приховане значення `_csrf` у заголовку `X-CSRF-TOKEN`; відправка історії надсилає його як поле форми `_csrf`. API-клієнти повинні зберігати cookie між запитами. Це форми, а не JSON-запити.

Описи мають бути непорожніми і не довше 1000 символів. Контролер обрізає опис та видаляє `<`, `>`, подвійні лапки, апострофи та `&` перед передачею сервісу. Шаблон результату також екранує вихід моделі з допомогою `th:text`.

Помилки валідації зображень повертають HTTP 400 з полем `error`; помилки моделі повертають HTTP 502 з полем `error` та без `description`. Невірні описи історій або помилки моделі перенаправляють на `/` із видимою помилкою. Відсутні обов’язкові поля повертають HTTP 400, а відсутні чи недійсні CSRF токени — HTTP 403. Жодних запасних описів або історій як успішних результатів ШІ не подається.

### 3. Сервіс історій

**Файл:** [StoryService.java](../../../../04-PracticalSamples/petstory/src/main/java/com/example/petstory/StoryService.java)

Офіційний OpenAI Java SDK 4.63.1 виконує виклики Azure AI Foundry OpenAI-сумісного API Chat Completions. Azure Identity 1.18.6 надає токен Microsoft Entra через `DefaultAzureCredential`; API-ключ не потрібен.

| Операція | Вхідні дані | `max_completion_tokens` |
| --- | --- | --- |
| `analyzeImage` | Байти зображення, закодовані у base64 data URL з типом MIME файлу | 300 |
| `generateStory` | Опис у повідомленні користувача | 800 |

Обидва запити використовують налаштоване розгортання, за замовчуванням `gpt-5.6-luna`, і явно встановлюють `ReasoningEffort.NONE` (`reasoning_effort: none`). Жоден запит не встановлює `temperature` або застарілий параметр `max_tokens`.

Аналіз зображень приймає JPEG, PNG, GIF і WebP, відкидає порожні зображення і файли понад 10 МБ, опис обмежений 1000 символами. Запит на історію вимагає сімейно-дружньої короткої історії. Порожні варіанти чи пустий контент моделі є помилками, а помилки зберігають оригінальну причину для серверної діагностики. Клієнт SDK закривається під час завершення роботи програми.

### 4. Веб-шаблони

**Файл:** [index.html](../../../../04-PracticalSamples/petstory/src/main/resources/templates/index.html) (Форма завантаження)

Сторінка починається з вибору фотографії, а не текстової області для опису. Кнопка **Analyze Image** попередньо показує вибране фото та відправляє його на `/analyze-image`. Успішна відповідь відображає опис, заповнює приховане поле `description` та показує кнопку **Generate Story**. Ця кнопка відправляє існуючу форму на `/generate-story`.

Завантаження моделі у браузер або залежності від CDN немає. Аналіз зображень виконується на сервері через налаштоване розгортання Azure. Помилки залишаються видимими та не дозволяють згенерувати історію із вигаданим описом. Вибір іншого файлу скидає попередній аналіз.

**Файл:** `result.html` (Відображення історії)

Відображає згенеровану історію:

```html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <title>Pet Story Result</title>
</head>
<body>
    <div class="container">
        <h1>Your Pet's Story</h1>
        
        <div class="result-section">
            <div class="result-label">Pet Description:</div>
            <div class="result-content" th:text="${caption}"></div>
        </div>
        
        <div class="result-section">
            <div class="result-label">Generated Story:</div>
            <div class="result-content" th:text="${story}"></div>
        </div>
        
        <div class="result-section" th:if="${analysisType}">
            <div class="result-label">Analysis Type:</div>
            <div class="result-content" th:text="${analysisType}"></div>
        </div>
        
        <a href="/" class="back-link">Generate Another Story</a>
    </div>
</body>
</html>
```

**Особливості шаблону:**

1. **Інтеграція Thymeleaf**: Використання атрибутів `th:` для динамічного контенту
2. **Адаптивний дизайн**: CSS-стилі для мобільних та настільних пристроїв
3. **Обробка помилок**: Відображення помилок валідації користувачам
4. **Обробка завантаження**: JavaScript попереднього перегляду фото, надсилання CSRF-захищеного multipart запиту та відображення отриманого опису

### 5. Конфігурація

**Файл:** `application.properties`

Налаштування конфігурації програми:

```properties
spring.application.name=pet-story-app

# File upload limits
spring.servlet.multipart.max-file-size=10MB
spring.servlet.multipart.max-request-size=10MB

# Logging configuration
logging.level.com.example.petstory=INFO

# Azure AI Foundry (keyless) configuration
azure.openai.endpoint=${AZURE_OPENAI_ENDPOINT:}
azure.openai.deployment=${AZURE_OPENAI_DEPLOYMENT:gpt-5.6-luna}
```

**Пояснення конфігурації:**

1. **Завантаження файлів**: Розмір файлу та загальний multipart-запит обмежені 10 МБ; зберігайте фото меншими за це обмеження, щоб залишити місце для заголовків multipart
2. **Логування**: Керує інформацією, що логуватиметься під час виконання
3. **Azure AI Foundry**: Задає кінцеву точку та розгортання моделі (автентифікація без ключа)
4. **Безпека**: Захист від CSRF увімкнено; діагностика моделі логуються на сервері, а контролер відображає загальні повідомлення про помилки моделі

## Запуск програми

### Крок 1: Увійдіть і встановіть кінцеву точку

Автентифікація відбувається без ключа (Microsoft Entra ID), тому API ключ не потрібен. Увійдіть і встановіть вашу кінцеву точку Foundry:

**Windows (Command Prompt):**
```cmd
az login
set AZURE_OPENAI_ENDPOINT=https://your-resource.openai.azure.com/
```

**Windows (PowerShell):**
```powershell
az login
$env:AZURE_OPENAI_ENDPOINT="https://your-resource.openai.azure.com/"
```

**Linux/macOS:**
```bash
az login
export AZURE_OPENAI_ENDPOINT=https://your-resource.openai.azure.com/
```

**Чому це потрібно:**
- Azure AI Foundry використовує Microsoft Entra ID для автентифікації запитів інференсу
- Автентифікація без ключа означає відсутність секретів у коді чи середовищі
- Ваш обліковий запис повинен мати роль **Cognitive Services OpenAI User** на ресурсі

Ім’я розгортання за замовчуванням — `gpt-5.6-luna`. Якщо ваше розгортання GPT-5.6 Luna має інше ім’я, встановіть `AZURE_OPENAI_DEPLOYMENT` у тому ж терміналі перед запуском програми. І аналіз зображень, і генерація історій використовують цей параметр.

### Крок 2: Збірка і запуск

Перейдіть у каталог проєкту:
```bash
cd 04-PracticalSamples/petstory
```

Зберіть автономний виконуваний JAR і запустіть усі офлайн тести:
```bash
mvn clean package
```

Запустіть сервер:
```bash
mvn spring-boot:run
```

Програма запуститься на `http://localhost:8080`.

Альтернативно, запустіть упакований JAR на вільному порту, наприклад:

```bash
java -jar target/pet-story-app-0.0.1-SNAPSHOT.jar --server.port=8083
```

Для цієї команди відкрийте `http://localhost:8083/`. Ті ж маршрути `/analyze-image` та `/generate-story` доступні на вибраному порту.

### Крок 3: Тестування програми

1. **Відкрийте** `http://localhost:8080` у браузері
2. **Виберіть** чітке фото домашнього улюбленця у форматах JPEG, PNG, GIF або WebP розміром менше 10 МБ
3. **Натисніть** "Analyze Image" і дочекайтеся опису улюбленця
4. **Натисніть** "Generate Story" після успішного аналізу
5. **Перегляньте** історію та використайте посилання на сторінці результату, щоб повернутися до форми завантаження

Успішний потік від фото до історії робить два виклики моделі, по одному на кнопку. Жива інференція споживає квоту вашого розгортання і може призвести до витрат; запускайте спочатку прості тести послідовно, якщо розгортання обмежене за швидкістю. Завантаження головної сторінки не викликає модель.

## Офлайн-тести

З каталогу прикладів запустіть:

```bash
mvn test
```

[StoryServiceTest.java](../../../../04-PracticalSamples/petstory/src/test/java/com/example/petstory/StoryServiceTest.java) захоплює реальні запити OpenAI SDK за допомогою HTTP-фікстури loopback. Перевіряє розгортання обох запитів, `reasoning_effort: none`, ліміти токенів, вантаж зображення, валідацію вводу, порожні відповіді та помилки на стороні сервера.

[PetControllerTest.java](../../../../04-PracticalSamples/petstory/src/test/java/com/example/petstory/PetControllerTest.java) використовує MockMvc із змодельованим сервісом моделі для тестування відрендерених сторінок Thymeleaf, контракту завантаження, CSRF, валідації, екранування виводу та видимих збоїв. Ці тести не вимагають Azure облікових даних і ніколи не викликають платний Azure inference. Maven записує звіти Surefire у `target/surefire-reports`.

## Як це все працює разом

Ось повний потік при генерації історії про домашнього улюбленця:

1. **Вибір фото**: Ви обираєте зображення домашнього улюбленця у формі завантаження
2. **Завантаження зображення**: "Analyze Image" надсилає multipart POST на `/analyze-image` з CSRF-заголовком
3. **Аналіз зображення**: `StoryService` надсилає зображення GPT-5.6 Luna з `reasoning` встановленим у `none`
4. **Відображення опису**: Браузер показує отриманий опис і зберігає його в формі
5. **Відправка історії**: "Generate Story" відправляє `description` і `_csrf` на `/generate-story`
6. **Генерація історії**: Контролер валідує опис і викликає те саме розгортання з `reasoning` в `none`
7. **Рендеринг шаблону**: Thymeleaf екранує і відображає опис та історію на сторінці результату

**Потік обробки помилок:**
Якщо модель не працює, сервер логують причину. Аналіз зображень повертає HTTP 502, і браузер показує помилку без відображення кнопки "Generate Story". Генерація історії перенаправляє на форму з повідомленням про помилку. Жоден шлях не підмінює результат на заздалегідь написаний.

## Розуміння інтеграції ШІ

### Azure AI Foundry (без ключа)
Сервіс налаштовує SDK з кінцевою точкою вашого ресурсу `/openai/v1/`. `DefaultAzureCredential` та `AuthenticationUtil.getBearerTokenSupplier` постачають токени Microsoft Entra для `https://ai.azure.com/.default`. Локальна розробка може використовувати вхід через Azure CLI; хостингова програма Azure може використовувати керовану ідентичність з необхідними дозволами на ресурс.

### Інженерія підказок
Аналіз зображень запитує спостережувані ознаки домашнього улюбленця у короткому абзаці і каже моделі трактувати текст на зображенні як дані, а не інструкції. Генерація історій використовує отриманий опис в окремому запиті на сімейно-дружню розповідь. Жоден виклик не активує reasoning або не встановлює температуру.

### Обробка відповіді
Спільний обробник відповіді відкидає відсутні вибори і порожній або лише пробільний контент, обрізає дійсний вміст і зберігає помилки зверху. Опис зображення обмежений 1000 символами для помістити у форму історії. Початкова помилка моделі зберігається для діагностики, проте не відображається користувачу.
