# ഫൗണ്ടറി ലോക്കൽ സ്പ്രിംഗ് ബൂട്ട് ട്യൂട്ടോറിയൽ

നിങ്ങളുടെ സ്വന്തം машиныൽ ചെറിയ ഒരു ഭാഷാ മാതൃക പ്രവർത്തിപ്പിക്കാനും അതിന്റെ OpenAI-അനുരൂപമായ
REST എണ്ട്പോയിന്റ് ഒരു ജാവ കോൺസോൾ ആപ്ലിക്കേഷനിൽ നിന്ന് കോൾ ചെയ്യാനും. ഏത് അസ്യൂർ ഡിപ്ലോയ്മെന്റും, അസ്യൂർ സൈൻ-ഇൻ,
ക്ലൗഡ് API കീ, അല്ലെങ്കിൽ ക്ലൗഡ് ഇൻഫറൻസ് വേണ്ട. **GPT-5.6 ലൂണ അസ്യൂർ-ഒണ്ലിയാണ്; ഫൗണ്ടറി ലോക്കൽ
മോഡലായി അതിനെ കോൺഫിഗർ ചെയ്യരുത്.**

## പതിപ്പുകളും മുൻകൂട്ടി ആവശ്യകതകളും

| ഘടകം | പതിപ്പ് |

| മേവൻ | 3.6.3 അല്ലെങ്കിൽ പിന്നീട് |

| നോഡ്.js (ലോകൽ REST സെർവർ) | 20 അല്ലെങ്കിൽ പിന്നീട് |
| ഫൗണ്ടറി ലോക്കൽ CLI (ഐച്ഛികം, ശേഖരമറിയിപ്പ്) | 0.10.3 പ്രിവ്യൂ |

സ്പ്രിംഗ് ബൂട്ട് സ്പ്രിംഗ് ഫ്രെയിംവർക്ക്, ജാക്സൺ, JUnit, മേവൻ പ്ലഗിന്റെ പതിപ്പുകൾ നിയന്ത്രിക്കുന്നു.
ഈ ഉദാഹരണം നേരിട്ടു ഓപ്പൺഎഐ ജാവ SDK ആണ് ഉപയോഗിക്കുന്നത്, സ്പ്രിംഗ് AI അല്ല. പഴയ ഉപയോഗം ഇല്ലാത്ത
സ്പ്രിംഗ് AI മൈല്സ്ടോൺ പ്രോപ്പർട്ടി, റിപ്പോസിറ്ററി നീക്കം ചെയ്തിരിക്കുന്നു.

നിർദ്ദേശിക്കപ്പെട്ട സ്റ്റാർട്ടർ മോഡൽ **Qwen 2.5 0.5B**, CPU വകഭേദം
`qwen2.5-0.5b-instruct-generic-cpu:4` (ദ്രുതഗതിയിൽ ഏതാണ്ട് 822 എം.ബി. കാറ്റലോഗിൽ).
GPU എക്സിക്യൂഷൻ പ്രൊവൈഡർമാരെ ആവശ്യപ്പെടേണ്ടതില്ല. മറ്റ് പിന്തുണയുള്ള, കാഷ് ചെയ്ത ചെറിയ മോഡലുകൾ
പ്രത്യേകം തെരഞ്ഞെടുത്തിരിക്കാം. മോഡൽ, റൺടൈം ഇൻസ്റ്റലേഷൻക്ക് നെറ്റ്‌വർക്ക് ആക്‌സസ് ആവശ്യമാണ്;
പ്രോംപ്റ്റുകളും ഇൻഫറൻസും ലോക്കലായിരിക്കും. ഫൗണ്ടറി ലോക്കൽ ഉപേക്ഷിക്കത്തക്ക ടെലിമെട്രി ഡിസേബിൾ ചെയ്താലും
ചെറിയ റണ്‍ടൈം ഡയഗ്നോസ്റ്റിക് പുറപ്പെടുവിച്ചേക്കാം.

ഈ സാമ്പിൾ ഡയറക്ടറിയിൽനിന്ന് താഴെ കാണുന്ന കമാൻഡുകൾ ഓടിക്കുക.

## ജാവ നിർമ്മിക്കുക, പരീക്ഷിക്കുക

```powershell
mvn clean verify
```

HTTP കരാറിന്റെ ടെസ്റ്റുകൾ ഒരു താൽക്കാലിക ലൂപ്പ്‌ബാക്ക് സെർവർ ആരംഭിക്കുകയും യഥാർത്ഥ
ഓപ്പൺഎഐ ജാവ SDK ഉപയോഗിച്ച് പരീക്ഷണങ്ങൾ നടത്തുകയും ചെയ്യുന്നു. അവ അപേക്ഷയുടെ സീരിയലൈസേഷൻ, മോഡൽ കണ്ടെത്തൽ,
വ്യക്തമായ മോഡൽ തിരഞ്ഞെടുപ്പ്, സംശയാസ്പദമോ തെറ്റായ മോഡൽ പട്ടികകൾ, HTTP തകരാർ,
ശൂന്യ ഫലങ്ങൾ, ലോക്കൽ മാത്രം URLs, കമാൻഡ്-ലൈൻ തകരാർ പ്രചരിക്കൽ എന്നിവ ഉൾക്കൊള്ളുന്നു. മോഡലോ
നെറ്റ്‌വർക്ക് ആക്‌സസ് മേവൻ ഡിപൻഡൻസി ഇൻസ്റ്റലേഷൻക്ക് പുറത്തായി ആവശ്യമില്ല. ലൈവ് ടെസ്റ്റ് ഓപ്റ്റ്-ഇൻ ആണു.

## ലോക്കൽ മോഡൽ തുടങ്ങുക

### നിർദ്ദേശം: പിന്‍ ചെയ്ത SDK സെർവർ

നെയ്റ്റീവ് ഫൗണ്ടറി ലോക്കൽ ജാവ SDK ഇല്ല. ചെറിയ നോഡ്.js സഹായി ഔദ്യോഗിക SDKയുടെ REST സെർവർ ഹോസ്റ്റ് ചെയ്യുന്നു;
ആപ്ലിക്കേഷൻ, ചാറ്റ് അഭ്യർത്ഥന ജാവയിലായിരിക്കും തുടരുന്നത്.

പിന്‍ചെയ്ത റൺടൈം ഡിപെൻഡൻസി ഇൻസ്റ്റാൾ ചെയ്യുക:

```powershell
npm ci
```

വിൻഡോസ് x64 SDKയുടെ നെയ്റ്റീവ് ഇൻസ്റ്റലേഷനിൽ ന്യുഗെറ്റ് എത്താനാകുന്നില്ലെങ്കിൽ, നൽകിയ ഫാല്ബാക്ക് ഉപയോഗിക്കുക.
അത് യോജിക്കുന്ന ഔദ്യോഗിക GitHub റണ്‍ടൈം ആർക്കൈവ് ഡൗൺലോഡ് ചെയ്ത് റിലീസിന്റെ SHA-256 ഡൈജസ്റ്റ് പരിശോധിച്ച്,
അതിന്റെ DLLകൾ നെയ്റ്റീവ് അഡോണിന്റെ അടിയിൽ സ്റ്റേജ് ചെയ്യുന്നു. TLS പരിശോധനാ നീക്കം ചെയ്യുന്നില്ല,
എലവേഷൻ ആവശ്യപ്പെടുന്നില്ല, SDK സ്രോതസ് മാറ്റുന്നില്ല.

```powershell
npm ci --ignore-scripts
pwsh -File ./scripts/install-foundry-runtime.ps1
```

ഈ മെഷീനിൽ ഇതിനകം കാഷ് ചെയ്ത മോഡലുകൾ പട്ടിക പറയുക:

```powershell
npm run start:foundry -- --list
```

ആദ്യ റൺക്ക്, ചെറിയ CPU മോഡൽ ഡൗൺലോഡിന് വ്യക്തമായി അനുവാദം നൽകുക:

```powershell
npm run start:foundry -- --model qwen2.5-0.5b-instruct-generic-cpu:4 --download --port 5273
```

അടുത്ത റൺസിൽ `--download` ഒഴിവാക്കുക, കാഷ് ചെയ്ത മോഡൽ ആവശ്യമാണ് എന്ന് സൂചിപ്പിക്കുക:

```powershell
npm run start:foundry -- --model qwen2.5-0.5b-instruct-generic-cpu:4 --port 5273
```

സഹായി യോജിച്ച കാഷ് മോഡൽ മുൻഗണന നൽകുന്നു, ഒരു അലിയാസ് അല്ലെങ്കിൽ ശരിയായ വകഭേദ ID സ്വീകരിക്കുന്നു,
`--download` നൽകി ഇല്ലെങ്കിൽ നഷ്ടപ്പെട്ട മോഡലിനെ തള്ളി. തിരഞ്ഞെടുക്കപ്പെട്ട മോഡലിന്റെ എക്സിക്യൂഷൻ പ്രൊവൈഡർ മാത്രം
രജിസ്റ്റർ ചെയ്യും, അതിനുള്ള ആവശ്യമുണ്ടെങ്കിൽ. കാഷ് ചെയ്ത GPU വകഭേദങ്ങൾക്കും ഇനിയും യോജിച്ച
എക്സിക്യൂഷൻ-പ്രൊവൈഡർ പാക്കേജുകളും ഡ്രൈവർകളും ആവശ്യമായേക്കാം.

പോർട്ട് 5273 ഉപയോഗത്തിൽ ആണെങ്കിൽ, ലഭ്യമായ പോർട്ട് എടുക്കാൻ `--port 0` പാസ്സ് ചെയ്യുക. സഹായി
`FOUNDRY_LOCAL_BASE_URL`, ശരിയായ `FOUNDRY_LOCAL_MODEL` ID,യും അത് റെഡി ആകുമ്പോൾ PIDയും പ്രിന്റ് ചെയ്യും.
ജാവയിൽ പ്രസിദ്ധീകരിച്ച എന്റ്പോയിന്റ് ഉപയോഗിക്കുക. ജാവ പ്രവർത്തിപ്പിക്കുമ്പോൾ ഇവൻ ടെർമിനൽ തുറന്നുവെക്കുക;
**Ctrl+C** REST സെർവർ നിർത്തുകയും മോഡൽ വിട്ടുകിട്ടുകയും ചെയ്യും.

ഡിഫോൾട്ട് കാഷെയുടെ സ്ഥലം `~/.foundry/cache/models`. മറ്റൊരു നിലവിലുള്ള കാഷ് വേണ്ടെങ്കിൽ
`FOUNDRY_LOCAL_CACHE_DIR` സജ്ജീകരിക്കുക. ലോഗുകളും സഹായിയുടെ സ്ഥിതിവിവരവും ഈ സാമ്പിളിന്റെ
`target/foundry-local` ഡയറക്ടറിയിൽ എഴുതുന്നു. `mvn clean` ഓടിക്കുന്നതിന് മുമ്പ് സഹായി നിർത്തുക.

### ഐച്ഛികം: ഫൗണ്ടറി ലോക്കൽ CLI

CLIയും SDKയും സ്വതന്ത്ര റിലീസുകളാണ്: CLI **0.10.3** SDK **1.2.4** ഉപയോഗിക്കുന്നു;
മേൽപ്പറഞ്ഞ സഹായി SDK **2.0.1** ഉപയോഗിക്കുന്നു. പുതിയ CLI ഇൻസ്റ്റാൾ ചെയ്താൽ
പുതിയ ഭാഷാ SDK ഇൻസ്റ്റാൾ ചെയ്യപെടുകയില്ല. [CLI റിലീസ് നോട്ട്സ്](https://github.com/microsoft/Foundry-Local/releases/tag/cli-preview-0.10.3) കാണുക.

വിൻഡോസിൽ CLI ഇല്ലെങ്കിൽ ഓരോ ഉപയോക്താവിനും ഇൻസ്റ്റാൾ കമാൻട് ഉപയോഗിക്കുക:

```powershell
winget install --id Microsoft.FoundryLocal --exact --source winget --scope user --silent --accept-package-agreements --accept-source-agreements --disable-interactivity
```

അല്ലെങ്കിൽ നിലവിലുള്ള ഇൻസ്റ്റലേഷൻ അപ്ഗ്രേഡ് ചെയ്യുക:

```powershell
winget upgrade --id Microsoft.FoundryLocal --exact --source winget --scope user --silent --accept-package-agreements --accept-source-agreements --disable-interactivity
foundry --version
```

CLI 0.10.x പഴയ `foundry service` കമാൻഡുകൾ `foundry server` കമാൻഡുകളിൽ മാറ്റി:

```powershell
foundry server start --port 5273
foundry cache list
foundry model load qwen2.5-0.5b-instruct-generic-cpu:4
foundry server status --output json
```

`model load`-ന് ഇതിനകം ഡൗൺലോഡ് ചെയ്ത മോഡൽ വേണം. ഡൗൺലോഡ് കമാൻഡുകൾക്കായി
`foundry model --help` ചെക്ക് ചെയ്യുക. സ്റ്റാറ്റസ് ഔട്ട്പുട്ടിലെ യഥാർത്ഥ എന്റ്പോയിന്റ് ഉപയോഗിക്കുക;
CLI സ്വയം അനുവദിച്ച പോർട്ട് ഡിഫോൾട്ട് ആക്കുന്നു. CLIയും SDK സഹായിയും ഒരേ പോർട്ടിൽ
തുടങ്ങിയാൽ പറ്റില്ല. നിർവഹിച്ചതിന് ശേഷം:

```powershell
foundry server stop
```

## ജാവ ആപ്ലിക്കേഷൻ പ്രവർത്തിപ്പിക്കുക

രണ്ടാമത്തേത് ടെർമിനലിൽ, നിങ്ങളുടെ സെർവർ പ്രിന്റ് ചെയ്ത എന്റ്പോയിന്റ്, ശരിയായ മോഡൽ ID സെറ്റ് ചെയ്യുക:

```powershell
$env:FOUNDRY_LOCAL_BASE_URL = "http://127.0.0.1:5273/v1"
$env:FOUNDRY_LOCAL_MODEL = "qwen2.5-0.5b-instruct-generic-cpu:4"
mvn spring-boot:run
```

അല്ലെങ്കിൽ പാക്കേജ് ചെയ്ത ആപ്ലിക്കേഷൻ ഓടിക്കുക:

```powershell
java -jar target/foundry-local-spring-boot-0.0.1-SNAPSHOT.jar
```

ഒറ്റ ജാവ എൻട്രിപോയിന്റ് `com.example.Application`. ഇത് തിരഞ്ഞെടുക്കപ്പെട്ട
എന്റ്പോയിന്റ്, യഥാർത്ഥ മോഡൽ ID, പ്രോംപ്റ്റ്, സൃഷ്ടിച്ച മറുപടി പ്രിന്റ് ചെയ്തശേഷം സ്പ്രിംഗ്
കോൺടെക്സ്റ്റും HTTP ക്ലയന്റും അടയ്ക്കുന്നു. പരാജയപ്പെട്ട ഇൻഫറൻസ് അല്ലെങ്കിൽ മറുപടി ടെക്സ്റ്റ് ഇല്ലെങ്കിൽ
വിജയകരമായ പ്ലേസ്ഹോൾഡറിന്റെ പകരം പരാജയ പ്രകടനം കാണിക്കും.

### കോൺഫിഗരേഷൻ

| പരിസ്ഥിതി വ്യാരി | ഡിഫോൾട്ട് | ഉദ്ദേശ്യം |
| --- | --- | --- |
| `FOUNDRY_LOCAL_BASE_URL` | `http://127.0.0.1:5273/v1` | ലൂപ്പ്‌ബാക്ക് HTTP എന്റ്പോയിന്റ്, `/v1` ഉൾപ്പെടെ |
| `FOUNDRY_LOCAL_MODEL` | ശൂന്യം | യഥാർത്ഥ മോഡൽ ID; അല്ലെങ്കിൽ ഒറ്റ പ്രചരിപ്പിച്ച മോഡൽ തിരഞ്ഞെടുക്കുന്നു |
| `FOUNDRY_LOCAL_PROMPT` | ലോക്കൽ മോഡലുകളെ കുറിച്ചുള്ള ഒരു വാക്യ ചോദ്യമാണ് | കോൺസോൾ റണ്ണർ അയക്കുന്ന പ്രോംപ്റ്റ് |

സമാനമായ സ്പ്രിംഗ് ആർഗുമെന്റുകൾ: `--foundry.local.base-url=...`,
`--foundry.local.model=...`, `--foundry.local.prompt=...`.
ലൂപ്പ്‌ബാക്ക് HTTP എന്റ്പോയിന്റുകൾ മാത്രം സ്വീകരിക്കുന്നു. റിമോട്ട്/ക്ലൗഡ് എന്റ്പോയിന്റുകൾ,
എൻബെഡഡ് ക്രെഡൻഷ്യൽസുകൾ, ക്വറി സ്ട്രിംഗ്, `/v1` ഇല്ലാത്ത പാതകൾ നിരസിക്കുന്നു.

ശൂന്യമായ മോഡൽ ക്രമീകരണം `/v1/models` യഥാർത്ഥത്തിൽ ഒറ്റ മോഡൽ പ്രചരിപ്പിക്കുമ്പോഴേ തുടരും.
പ്രചരിച്ച മോഡൽ നിർബന്ധമായും ലോഡ് ആയതല്ല. ഒട്ടനവധി മോഡലുകൾ പ്രചരിപ്പിച്ചാൽ,
കാറ്റലോഗ് ഓർഡറിങ്ങിൽ ആശ്രയിക്കാതെ യഥാർത്ഥ ലോഡുചെയ്ത ID സജ്ജമാക്കുക.

അഭ്യർത്ഥനകൾ `temperature=0`, 150-ടോക്കൺ ഔട്ട്പുട്ട് പരിധി, 120 സെക്കന്റ് ടൈംഔട്ട്,
യാതൊരു സ്വയം ശ്രമങ്ങളും ഇല്ലാതെ എന്നിവ ഉപയോഗിക്കുന്നു. `max_tokens` അഭ്യർത്ഥന ഫീൽഡ് ഉദ്ദേശിച്ചത്:
ഫൗണ്ടറി ലോക്കൽ REST കരാറിലൂടെ പിന്തുണയ്ക്കുന്നു, അതോപ്പൺഎഐ ജാവ ഡിപ്രീക്കേറ്റ് ചെയ്യുന്നു.
ആ ഫീൽഡ് പുതിയ ക്ലൗഡ് മോഡലുകൾക്ക്. മോഡൽ ഐഡന്റിറ്റി കോൺഫിഗറേഷൻ അല്ലെങ്കിൽ
ഡിസ്കവറിയിൽ നിന്ന് വരുന്നു, മോഡൽ തന്റെ സംവാദങ്ങളിൽ നിന്നല്ല.

## ലൈവ് വെരിഫിക്കേഷൻ

ലോക്കൽ സെർവർ പ്രവർത്തിക്കുന്നതിനിടെ, ഓപ്റ്റ്-ഇൻ ലൈവ് ടെസ്റ്റ് അടങ്ങിയ എല്ലാ ടെസ്റ്റുകളും ഓടിക്കുക.
നിങ്ങളുടെ സെർവർ പ്രിന്റ് ചെയ്ത മൂല്യത്തോടെ എന്റ്പോസ്റ്റ് പോർട്ട് മാറ്റുക. പവർഷെല്ലിൽ ഡോട്ട് ചെയ്ത
Maven പ്രോപ്പർട്ടീസ് ഉദ്ധരിക്കുക:

```powershell
mvn "-Dfoundry.local.live=true" "-Dfoundry.local.base-url=http://127.0.0.1:5273/v1" "-Dfoundry.local.model=qwen2.5-0.5b-instruct-generic-cpu:4" verify
```

ലൈവ് ടെസ്റ്റ് `Application.main` വിളിക്കുന്നു, "ഫ്രാൻസിന്റെ തലസ്ഥാനം പാരിസ് ആണ്" എന്ന് വ്യക്തമായ വിവരം നൽകുകയും,
സിറ്റി ചോദിക്കുകയും, യാഥാർത്ഥ്യത്തിൽ സൃഷ്ടിച്ച ടെക്സ്റ്റ് `Paris` ആണെന്ന് ഉറപ്പാക്കുന്നു.
ഇത് HTTP സ്റ്റാറ്റസിൽ വിജയത്തോടെ മാത്രമല്ല, സെമാന്റിക് ഫലം പരിശോധിക്കുന്നു.

ഇത് ഇന്റഗ്രേഷൻ പരിശോധനയാണ്, കൃത്യത ബेंച്ച്മാർക്ക് അല്ല. വെരിഫിക്കേഷനിൽ, ഈ
0.5B മോഡൽ ജാവയിലും നേരിട്ട് REST വഴിയും "2 + 2" പ്രോഗ്രാംറെത്തിച്ച് `3` നൽകി.
സ്വതന്ത്രമായി പരിശോധിക്കാതെ ഗണിതനിർണയം അല്ലെങ്കിൽ വാസ്തവ കൃത്യതയ്ക്ക് ഇത് ആശ്രയിക്കരുത്;
കണക്കുകൾക്ക് നിർവ്വചിത ഉപകരണങ്ങൾ ഉപയോഗിക്കുക.
